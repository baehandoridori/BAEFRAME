# 경쟁 앱 공식 출처와 UX 비교 기준

조회일: 2026-09-06 KST. 리뷰 앱 2개(Frame.io V4·SyncSketch), 편집 앱 1개(Adobe Premiere), 일반 플레이어 1개(VLC)의 공식 문서 8개를 핵심 근거로 선정했다.

이 자료는 **공식 문서에 명시된 기능과 그로부터 도출한 설계 원칙**이다. 경쟁 앱을 직접 조작한 사용성 시험, 전환 속도 측정, 화면 대비·글자 크기 측정 또는 기능 개수에 따른 순위가 아니다. 마지막 열은 배프레임에 대한 제안이며 출처 제품이 보장하는 동작으로 해석하지 않는다.

## 해석할 때 지킬 경계

- SyncSketch 연속 재생 문서는 도입부와 중간의 요금제 설명이 완전히 일치하지 않는다. 기능 설계의 존재를 근거로 삼고, 현재 모든 계정·브라우저에서 쓸 수 있다고 단정하지 않는다.
- Adobe 모니터 버튼 문서는 조작부 그룹화의 근거다. 배프레임보다 화면 가시성이 좋다는 직접 증거가 아니다.
- Frame.io 비율 가이드는 화면 구성 확인 도구다. 이를 일반적인 UI 안전 여백이나 드로잉 좌표 정확도 보장으로 해석하지 않는다.
- 경쟁 제품도 제출 시점 프레임 연결이나 특정 전체화면 표시 제약처럼 고려할 점이 있다. 기능을 그대로 복제하기보다 배프레임의 코멘트·드로잉 리뷰 목적에 맞는 동작을 정해야 한다.

## 보고서 평가 기준으로 도출한 제안

1. **현재 대상을 확실히 표시한다.** 파일·버전·프레임과 코멘트·그림이 같은 대상을 가리키는지 확인한다.
2. **작성에서 재확인까지 이어 준다.** 의견 추가, 그림 발견, 해당 프레임 복귀, 처리 상태 확인, 수정 버전 확인을 하나의 흐름으로 평가한다.
3. **전환 중 리뷰 맥락을 보존한다.** 자동 이어보기·다음 파일 버튼·프레임 이동을 구분하고, 작성 중인 의견이나 그림의 대상이 바뀌지 않는지 검증한다.
4. **영상 면적과 작업 상태를 함께 보호한다.** 패널을 접더라도 코멘트 진입점·현재 프레임·그림 존재·저장 상태를 쉽게 확인할 수 있어야 한다.
5. **공유 결과를 수신자 관점에서 검증한다.** 링크 생성 성공만으로 완료 처리하지 말고, 같은 영상·프레임·그림·의견을 수신자가 확인할 수 있는지 검사한다.

위 제안은 공식 문서의 사실에서 도출한 분석이다. 배프레임의 현재 구현 여부와 결함 여부는 앱 화면·현행 소스·실행 근거에 별도로 연결해야 한다.

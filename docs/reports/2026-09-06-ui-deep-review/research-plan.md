# UI 심층 조사 계획과 증거 기준

대상: 2026-09-06, BAEFRAME 2.9.0-beta 개발본 `5d1cb89`. 사용자는 비개발자이며 애니메이션 리뷰·드로잉·짧은 영상 제작을 위한 대대적 UI 개선 결정을 원한다. 기존 개발본과 UX 보고서는 보존하고 앱 코드를 수정하지 않는다.

## 결정할 질문

1. 리뷰와 제작에서 공유할 화면 구조와 분리할 작업 문맥은 무엇인가?
2. 프레임·키프레임·그림 유지·영상 정지·클립 시간축을 어떻게 오해 없이 표시할 것인가?
3. 도구·선택·포커스·저장·협업 상태를 어떤 공통 시각 규칙으로 표현할 것인가?
4. 작은 창과 높은 표시 배율에서도 어떤 작업을 항상 보장할 것인가?
5. 어떤 순서로 바꾸고, 어떤 실제 작업 검증을 통과해야 다음 단계로 넘어갈 것인가?

## 진행

- 조사 완료: 리뷰13상태·편집14상태, 공식5제품15문서6이미지, W3C/Microsoft 기준 수집.
- 교차 확인 완료: 세 담당자의 독립 사실 검토, 과거 개선 보존, 출력 규격·정지 시간 표현 정정 및 한계 명시.
- 종합 완료: 14장·26개 항목, 문제-영향-원인-해결-부작용-검증 기준, 대안 비교, 미구현 제안도4개, 과제6개.
- 문서 검증 완료: HTML 링크·이미지·출처·실측 수치 및 제안 그림 텍스트 경계 확인. 비공개 게시 및 로컬 보존 결과는 publication.json과 DEVLOG에 기록한다.

계획 갱신 전용 도구는 이 환경에 없어 이 문서를 진행 기준으로 사용한다.

## 증거 수준

- A: 실제 현재 앱/프로덕션 화면을 격리 테스트 데이터로 조작·측정.
- B: 현재 코드로 확인한 구조. 전체 사용자 동작이나 실사용 빈도는 증명하지 않음.
- C: 공식 타사 문서 또는 공식 UI 이미지. 동일 장비 성능 비교나 타사 직접 사용 시험은 아님.
- D: 위 근거를 바탕으로 한 설계 판단·제안. 구현된 결과 또는 사용자 연구 결과로 주장하지 않음.

실제 사용자 인터뷰, 실사용 로그 분석, 펜 하드웨어 전종, 다양한 모니터 간 DPI 이동, 수신자 계정·실제 클라우드 전송은 이번 조사와 별도다. 문제 개수를 채우기 위해 경미한 항목을 늘리지 않는다. 데스크톱 도구의 모든 컨트롤에 모바일 44px 기준을 일괄 적용하지 않는다.

## 근거 축과 종료 기준

현재 리뷰창 / 현재 편집창 / 타사 공식 UI 세 독립 축을 병행한다. root는 표준, 구조 비교, 중요 주장 재확인과 최종 종합을 맡는다. 각 핵심 결정에 현행 근거와 적용 가능한 해결·검증 기준이 있고, 추가 검색이 결정에 영향을 주지 않을 때 수집을 종료한다. 확인하지 못한 것은 확인 필요로 남긴다.

# 드로잉 키프레임 기능 — 현재 상태와 데이터 출처

> 갱신 기준: 2026-09-05, v2.9.0-beta, 점검 대상 커밋 `85fd0c2`. 코드와 구현 기록을 대조했으며 이번 문서 정리에서 앱 실기 검증은 재수행하지 않았다. 이후 변경은 아래 날짜별 절에 따로 적는다.
>
> 레거시는 `drawings`, mpv Fabric 경로는 `drawingsV3`를 사용한다. 레이어 모델은 `.bframe` 루트의 `drawingLayersV1`에 있다. 아래 기능표가 현재 상태의 기준이며, 과거 미구현 분석은 [보존 기록](history/drawing-keyframe-features-before-2026-09-05.md)으로 분리했다.
>
> 작업 전 [드로잉 작업 규칙](drawing-work-guide.md)을 읽는다. 기능 변경 시 관련 상태·데이터 출처·검증 기준을 함께 갱신한다.

## 타임라인 프레임 바의 펜 입력 (2026-11-12, v2.16.2-beta)

| 항목 | 현재 구현 |
|---|---|
| 프레임 바·눈금자 끌기 | pointer 이벤트로 받는다(2026-07). 손잡이·눈금자·트랙 영역에 `touch-action: none`. 누르면 포인터를 묶고(`setPointerCapture`) 문서의 `pointermove`·`pointerup`·`pointercancel` 로 따라가며, 놓은 좌표를 정수 프레임으로 확정한다(v2.11) |
| 마우스·손가락 | 엄격하다(v2.11 그대로). 누른 포인터(`pointerId`)의 이벤트만 받고, 주 포인터만 시작한다. 묶음이 풀리거나(`lostpointercapture`) 창이 포커스를 잃거나(`blur`) 취소되면(`pointercancel`) 끌기를 끝내고 **시작한 자리로 되돌린다** |
| 펜 | 너그럽다(v2.16.2-beta, `_isPenScrub`). 펜이 보낸 이동·뗌이면 `pointerId` 가 달라도 받고, 주 포인터가 아니어도 시작하고, 묶음 풀림과 포커스 잃음은 무시하고, 취소되면 **마지막으로 끈 자리에 둔다**. 닿지 않은 채(눌린 버튼도 필압도 없이) 보낸 이동은 끌기로 치지 않는다. Windows 의 펜은 닿기 전에는 마우스와 같은 경로로, 닿은 뒤에는 터치와 같은 경로로 들어온다. v2.11 의 엄격한 규칙은 실제 펜으로 검증된 적이 없고, 그 뒤 "펜으로는 프레임 바를 끌 수 없다"는 보고가 왔다 |
| 뗌을 받지 못한 끌기 | 끄는 도중에 새 누름이 오면 앞선 끌기를 마지막으로 끈 자리에서 끝내고 새로 시작한다(끄는 손가락이 있는 동안의 다른 손가락은 예외). 전에는 다음 창 포커스 변화까지 프레임 바를 끌 수 없었다 |
| 진단 기록 | 펜에서, 엄격한 규칙이었다면 끌기가 끊겼을 입력을 받아들이면 종류마다 한 번 WARN 으로 남긴다(`%APPDATA%\baeframe\logs\baeframe-<날짜>.log` 의 "펜으로 프레임 바를 끄는 중"). 종류: `lostpointercapture`·`blur`·`pointercancel`·`hover-move`·`pointer-id`·`not-primary`·`superseded` |

**실물 펜으로는 확인하지 못했다.** 주입할 수 있는 입력(마우스, 펜의 마우스 경로, 터치 경로)으로는 수정 전에도 프레임 바가 끌려 재현되지 않았고, 실물 펜의 입력 경로는 만들어 넣을 수 없었다. 어느 규칙이 실제로 걸리는지는 위 진단 기록으로 확인한다. 근거는 [작업 기록](../DEVLOG/2026-11-12-timeline-pen-scrub.md).

## 패널을 닫은 채 한 프레임 조작의 실행취소 순서 (2026-11-12, v2.16.1-beta)

| 항목 | 현재 구현 |
|---|---|
| 표식에 붙는 전역 히스토리 리비전 | 패널을 닫은 채 한 프레임 조작의 표식에는 조작을 **요청한 때**의 전역 히스토리 리비전을 붙인다(`applyDrawingActionDetailed` 가 읽어 `rememberPassiveHistory` 에 넘긴다). v2.16.0-beta 까지는 응답이 온 때의 값을 붙였다. 그래서 응답을 기다리는 사이에 전역 작업(댓글 편집 등)을 하면, 먼저 한 프레임 조작이 마지막으로 한 일로 보여 Ctrl+Z 가 나중에 한 전역 작업 대신 프레임 조작을 되돌렸다. 지금은 그 표식이 처음부터 낡은 것으로 걸러져 전역 실행취소가 먼저다(응답 뒤에 전역 작업을 한 경우와 같은 결과) |
| Ctrl+Z / Ctrl+Y 의 판정 시점 | **키를 누른 때** 무엇이 마지막으로 한 일이었는지로 판정한다. 응답 전이라 받아 둔 키는 큐에서 차례가 왔을 때 지금의 리비전이 아니라 누를 때 읽어 둔 리비전과 표식을 견준다(`peekPassiveHistory(direction, revision)`). 그래서 프레임 조작 직후에 누른 Ctrl+Z 는 그 뒤에 전역 작업이 생겨도 프레임 조작을 되돌린다. 되돌리기·다시 실행을 반대쪽 스택으로 옮길 때도 키를 누른 때의 리비전을 그대로 둔다 — 되돌리기 뒤에 새 전역 작업이 생기면 그 되돌리기는 다시 실행하지 않는다 |

코덱스 사후 리뷰(PR #235·#236 의 변경을 검토 전용 PR 로 다시 본 것)에서 나온 지적이다. 자동 검사로 확인했다. 근거는 [작업 기록](../DEVLOG/2026-11-12-codex-retro-review-passive-undo-order.md).

## 변형 상자: 기울이기 · 뒤집기 · 회전 중심점 · 손잡이 커서 (2026-11-12, v2.16.0-beta)

| 항목 | 현재 구현 |
|---|---|
| 손잡이 커서 | 손잡이가 **움직이는 방향**으로 고른다(`resizeCursorForDirection`): 모서리는 대각선, 변은 변에 수직이고 오브젝트의 각도만큼 함께 돈다. Fabric 7.4.0 은 손잡이가 오브젝트 한가운데에서 보이는 방향으로 골라(`findCornerQuadrant`) 길쭉한 획의 모서리에 가로 화살표를 줬다. 동작은 원래부터 맞았고 모양만 고쳤다 |
| 기울이기 | `Ctrl` + 변 손잡이. 위·아래 변은 가로로, 왼쪽·오른쪽 변은 세로로 밀고 **맞은편 변은 제자리**다. 무엇을 할지는 누르는 순간에 정해져, 끄는 도중에 `Ctrl` 을 떼거나 눌러도 바뀌지 않는다. 커서는 변을 따라 눕는다. Fabric 의 기울이기는 쓰지 않는다 — 포인터가 움직인 양을 화면 축으로만 읽어, 돌려 둔 획에서는 변을 따라 끌어도 기울지 않는다. 런타임이 상자의 축으로 읽고, 출발 모양에 밀림을 얹은 결과를 `scaleX`·`scaleY`·`skewX`·`skewY`(와 뒤집힘)로 다시 푼다(`skewSelection`). 각도는 건드리지 않아 상자가 돌지 않는다. 가로로 밀면 `skewX` 만, 세로로 밀면 (가로 기울임이 없을 때) `skewY` 만 바뀐다. 이미 가로로 기운 획을 세로로 밀면 크기와 두 기울임이 함께 바뀐다. 한계는 ±80° 이고 넘는 걸음은 받지 않는다 |
| 뒤집기 | 팔레트의 선택 설정에 **뒤집기 [좌우] [상하]** 버튼. 변형 상자가 뜬 동안에만 켜진다. **화면에서 본 방향**으로, 상자의 한가운데를 축으로 뒤집는다 — 돌려 둔 획은 각도가 반대 방향이 된다(`flipX` 또는 `flipY` 토글 + `angle → 360° − angle`). 손잡이를 반대편으로 넘겨서는 여전히 뒤집히지 않는다(`lockScalingFlip`). 손잡이로 하는 변형과 같은 길로 저장한다(`flipSelection` → `commitSelectionTransform`·`commitPendingLassoTransform`): 실행취소 한 단계이고, 외곽선도 같은 축으로 뒤집히며, 세워 둔 조각은 가르기와 뒤집기를 한 번에 저장한다. 손잡이를 끄는 중에는 받지 않는다 |
| 회전 중심점 | 평소에는 상자의 한가운데가 회전의 축이다. **`Ctrl`+클릭한 자리**가 축이 되고 그 자리에 십자 동그라미 표시가 뜬다. 상자 밖에도 놓을 수 있고, `Ctrl` 을 누른 채 끌면 따라온다. 놓인 표시는 `Ctrl` 없이 끌어 옮길 수 있다. 상자 한가운데 가까이(6 화면 픽셀 안)에 놓으면 한가운데로 돌아가고 표시가 사라진다. 그림 영역 밖으로는 나가지 않는다(나가면 다시 잡을 수 없다). 중심점은 **그 오브젝트 자신의 좌표**로 들고 있어(화면의 자리는 오브젝트의 행렬을 곱해 얻는다) 크기·기울이기·이동·뒤집기를 해도 그림의 같은 자리에 붙어 다닌다. 저장한 뒤에도 남아 같은 축으로 이어서 돌릴 수 있다(`keepSelectionPivot` — 씬을 다시 세우기 전의 자리를 적어 두었다가 새로 고른 것에 얹는다). **선택이 바뀌면 사라진다** — 문서에 저장하지 않는 화면 상태다. `Shift`+클릭으로 묶음에 획을 더하거나 빼도 사라진다(Fabric 은 같은 묶음 오브젝트를 고쳐 쓰지만 선택은 달라졌다). 보이는 손잡이 위에서는 그 손잡이가 우선이고(`Ctrl`+변 손잡이 = 기울이기), 모서리 바깥의 보이지 않는 회전 영역은 `Ctrl` 을 누른 동안 중심점 놓기에 양보한다. `Ctrl` 을 누른 채 가리키면 커서가 십자로 바뀐다. 씬을 바꾸지 않으므로 호스트의 누르기 확정 왕복을 기다리지 않는다 |
| 표시를 한가운데에 늘 띄우지 않는 이유 | 획의 한가운데를 잡아 옮기는 것이 가장 흔한 조작이다. 표시가 거기 있으면 획 대신 표시가 끌려간다(처음에는 그렇게 만들었다가 기존의 이동 검사가 실패했다). 그래서 옮겨 둔 중심점이 있을 때만 표시가 보이고 잡힌다 |
| `Ctrl` 판정 | 마우스는 포인터 이벤트에 실린 `ctrlKey` 만 본다. 펜·터치는 이벤트에 실려 오지 않는 환경이 있어 오버레이 문서가 본 키 상태를 함께 보되, **마지막 누름(키 반복 포함)에서 2.5초 안의 것만** 믿는다(`isTransformCtrlActive`). 뗌을 놓쳐 남은 표시(v2.13.2-beta 에서 고친 것과 같은 종류)가 여기까지 오면 선택 도구의 탭이 통째로 중심점 놓기로 넘어가 선택도, 선택 풀기도, 옮기기도 되지 않기 때문이다. 임시 지우개의 판정(`isCtrlActive`)은 그대로다. `Ctrl` 은 선택 도구에서 지금까지 쓰이지 않았다(브러시·펜에서는 임시 지우개다) |
| 저장 | 레코드의 `transform` 만 바뀐다(`skewX`·`skewY`·`flipX`·`flipY`·`angle`·`left`·`top`). 스키마는 그대로다. **배율은 항상 양수로, 뒤집힘은 `flipX`·`flipY` 로 적는다.** 묶음의 획은 행렬에서 다시 풀어 적는데 분해(`qrDecompose`)는 뒤집힘을 음수 세로 배율로 돌려준다. 그대로 적으면 그릴 때 뒤집히지 않은 모양이 된다(`path.set(record.transform)` 이 배율 다음에 레코드의 `flipY: false` 를 덮는다). `storedTransformFromDecomposition` 이 옮겨 적고, 같은 모양을 적는 두 표기 `(θ, flipX, flipY)`·`(θ+180°, !flipX, !flipY)` 가운데 하나만 골라 변형했을 때와 같은 쪽을 고른다. 편집창이 화면 비율이 다른 출력 크기에 맞춰 돌린 획을 늘일 때도 같다(`rescaleRecordTransform`) |
| 팔레트의 안내 | 변형 상자가 뜬 동안 선택 설정 아래에 "Ctrl+변 손잡이: 기울이기", "Ctrl+클릭: 회전 중심점" 두 줄이 뜬다. 편집창의 가로 도크에는 뒤집기 버튼만 있고 안내는 없다 |
| 기울인 뒤의 상자 | 상자는 기울어진 모양(평행사변형)이 아니라 그것을 감싸는 직사각형이다(Fabric 의 경계 상자). 그래서 기울인 획은 상자가 그림보다 넓어 보일 수 있다. 손잡이의 동작은 그 상자를 기준으로 한다 |

자동 검사(실제 Fabric 을 띄워 손잡이를 끄는 검사와 픽셀 대조 포함)와 패키지된 앱 점검으로 확인했다. 사람이 직접 조작하는 실기, 실물 펜 태블릿, 편집창 가로 도크의 버튼 배치는 미확인이다. 근거는 [작업 기록](../DEVLOG/2026-11-12-drawing-transform-skew-flip-pivot.md).

## 변형 상자 다듬기 · 어니언 스킨 설정 보존 · 단축키 거절 안내 (2026-11-11, v2.15.0-beta)

| 항목 | 현재 구현 |
|---|---|
| 크기 손잡이의 포인터 계산 | Fabric 은 포인터의 절대 위치를 크기로 바꾼다 — (고정점에서 포인터까지의 거리 − 선택 상자의 여백) ÷ 원래 크기. 이 계산을 런타임이 대신 한다(`resolveScalePointer`. 다듬은 좌표를 넘기는 동안 오브젝트의 `padding` 을 0 으로 둔다). ① **가는 선의 굵기 튐**: 선택 상자의 여백(획을 잡기 쉽게 두른 6 화면 픽셀)보다 얇은 획에서 아래쪽 손잡이(왼쪽 아래·오른쪽 아래·아래 변)를 잡으면 굵기가 몇 배로 튀던 문제를 고쳤다. Fabric 7.4.0 `getLocalPoint` 의 세로 방향 여백 처리 한 줄이 잘못돼 있다(`localPoint.y <= padding` — 음수 부호가 빠졌다). ② **납작해지는 구간**: 포인터가 고정점에서 여백 안쪽으로 들어오면 크기 0(조작 한계인 0.02 배)에 붙는다. Fabric 은 그 구간의 좌표를 그대로 써서 크기가 0 까지 줄었다가 도로 커졌다 — 가는 선은 손잡이를 몇 픽셀만 당겨도 그 구간이다. ③ **잡은 자리**: 손잡이를 한가운데에서 벗어나 잡아도 그만큼(마우스·펜 최대 4.5 화면 픽셀)이 첫 걸음에 크기로 얹히지 않는다. 작은 획에서 눈에 띄게 튀었고, 가는 선은 굵기가 몇 배로 바뀌었다. 여러 획을 고른 묶음에도 적용된다. **v2.14.0-beta 에는 세 문제가 모두 있었다** |
| 여러 획을 옮긴 뒤 | 고른 채로 남는다(v2.14.0-beta 까지는 풀렸다). 씬을 다시 세우고 같은 것을 다시 골라 변형 상자를 새 좌표에 맞춘다(`reselectMovedMultiSelection`). 빈 곳을 누르면 풀린다. 잘라 고른 조각 여러 개를 옮긴 뒤에도 같다. 묶음의 상자 안에서 끌면 묶음이 통째로 움직이므로, 그 안의 획 하나만 따로 잡으려면 먼저 빈 곳을 눌러 선택을 푼다 |
| 잘라 고른 조각의 변형 | 부분 선택으로 세워 둔 조각에도 변형 상자가 뜬다. 처음 변형되는 순간 원본 획을 조각으로 갈아 끼우고(옮길 때와 같다), 손을 떼면 `replaceObjects({ replacements, transforms })` 로 가르기와 변형을 한 번에 저장한다(`commitPendingLassoTransform`). 실행취소 한 단계이고 되돌리면 자르기 전의 획으로 돌아간다. 끌었다가 제자리에 놓거나 취소하면 획을 가르지 않는다. 저장할 수 없는 변형(배율 한도 밖)이거나 스토어가 거절하면 화면과 외곽선을 조작 전으로 되돌리고 세워 둔 선택을 푼다(`abandonPendingLassoCommit`). 조각의 외곽선은 변형이 시작되기 전에 적어 둔 본체 행렬을 기준으로 따라간다. 숨기거나 잠근 레이어의 획은 조각으로도 변형하지 않는다 |
| 어니언 스킨 설정 보존 | 켜짐·앞뒤 장수·진하기를 사용자 설정(`drawingOnionSkin`, 이 PC 전용)에 보존한다. 오버레이가 값이 바뀔 때마다 알리고(`mpvOverlayOnionSkinPrefs.notify` → `mpv-overlay:onion-skin-prefs` → `fabric-drawing:onion-skin-prefs`) 메인 창이 모아서 적는다. 오버레이가 받을 수 있는 상태가 되면(보기·그리기 모두) 다시 심는다(`fabric-onion-skin-prefs-pusher.js` → `mpv:apply-overlay-onion-skin-prefs` → `applyOnionSkinPrefs`). 기본값 그대로면 보내지 않고, 오버레이에 닿지 못했으면 0.5·1.5·4초 뒤에 다시 보낸다. 사용자가 그 창에서 값을 바꾼 뒤에는 저장값으로 덮지 않는다. 재생 여부는 설정이 아니라 보존하지 않는다. 한도와 검증은 `shared/fabric-onion-skin-prefs.js` 한 곳에 있다. 한계: 심기가 끝내 닿지 못한 오버레이에서 값을 바꾸면 그 오버레이의 기본값(장수·진하기)이 함께 저장된다(팔레트 값 보존과 같은 한계) |
| 프레임 단축키 거절 안내 | 오버레이가 사유를 붙여 거절하면 토스트로 알린다(`onFrameOperationRejected` → `FABRIC_PILOT_FRAME_OPERATION_REJECTIONS`). 마지막 프레임에 키프레임이 있어 더 넣을 수 없음(빈 키프레임이어도 같다)·이미 키프레임·키프레임이 아님·복사해 둔 프레임 없음·다른 영상의 프레임·복사할 그림 없음·그림이 너무 많음·범위 밖. 사유 없는 실패(전송 실패·낡은 요청)와 요청을 보내지도 못한 경우에는 띄우지 않는다 |

자동 검사로 확인했다. 실제 앱 조작과 실물 펜 태블릿은 아래 [작업 기록](../DEVLOG/2026-11-11-drawing-followups.md)의 검증 절을 따른다.

## 패널 없이 쓰는 단축키 · B 키 · 어니언 스킨 · 변형 상자 (2026-11-11, v2.14.0-beta)

| 항목 | 현재 구현 |
|---|---|
| 그리기 패널이 닫힌 상태의 프레임 단축키 | `2`·`3`·`4`·`Shift+2`·`Shift+3`·`Ctrl+Alt+C`·`Ctrl+Alt+V`(§1.1·§1.2 의 파일럿 씬 조작 7종)가 패널을 열지 않아도 동작한다. 세션 id 가 없으므로 **영상 정체**(호스트 세대·영상 세대·입력 리비전·`stableVideoIdentity`)로 맞춘다. 레거시 F6/F7 과 레이어 단축키는 종전대로다 |
| 패널이 닫힌 상태의 Ctrl+Z / Ctrl+Y | **패널을 닫은 채 한 프레임 조작만** 되돌린다. 조작마다 표식(`historyToken`)을 받아 두고, 구조 히스토리의 맨 위가 그 표식일 때만 되돌린다. 패널을 열어 그린 획이나 그 사이의 다른 편집이 맨 위에 있으면 건드리지 않고 기존 전역 히스토리 경로로 넘어간다. 조작의 응답이 오기 전에 누른 Ctrl+Z 는 키를 받아 두었다가 조작이 끝난 뒤에 판정한다(표식은 응답이 와야 안다. 기다림은 2초까지다). 판정할 때 닫은 채 한 조작이 맨 위가 아니거나 오버레이가 히스토리가 비었다고 답하면 전역 실행취소로 넘기고, 맨 위에 다른 항목이 있다는 답과 전송 실패에는 넘기지 않는다. 표식은 패널을 열거나 영상을 다시 수화하거나 전역 히스토리가 실제로 움직이면 버린다(최대 32개). 표식에 붙는 리비전은 v2.16.1-beta 부터 조작을 요청한 때의 값이다(맨 위 절) |
| `B` | 패널이 닫혀 있으면 연다(마지막에 쓰던 도구 그대로). 패널이 열려 있고 **다른 도구**를 쓰는 중이면 브러시를 고른다. 패널이 열려 있고 **브러시**를 쓰는 중이면 닫는다. 판정은 오버레이가 돌려준 "바꾸기 전 도구"(`previousTool`)로 한다 — 렌더러의 사본으로 판정하면 팔레트를 눌러 바꾼 도구를 모른다 |
| 어니언 스킨 | `1`(`onionSkinToggle`)과 팔레트의 어니언 스킨 줄로 켠다. 패널이 닫혀 있어도 켜고 끌 수 있다. 앞 그림은 파랑, 뒤 그림은 초록으로 겹쳐 보인다. 장수(앞 0~5·뒤 0~5, 기본 앞 2·뒤 1)와 진하기(10~80%, 기본 30%)는 팔레트에서 바꾼다. **장**은 키프레임 한 장이다(홀드 프레임을 세지 않는다). 빈 키프레임은 건너뛰고, 숨긴 레이어의 획은 그리지 않으며, 재생 중에는 숨긴다 |
| 어니언 스킨이 그려지는 자리 | Fabric 캔버스 **아래**의 별도 캔버스다. 씬·선택·저장에 들어가지 않고 `drawingsV3` 도 바뀌지 않는다. 설정값은 v2.15.0-beta 부터 사용자 설정에 보존한다(위 절). 편집창 도크에는 어니언 스킨 줄이 없다 |
| 선택 도구의 변형 상자 | `V` 로 고른 획(여러 개 포함)에 손잡이가 달린 상자가 뜬다. 모서리 = 크기(가로·세로 따로, `Shift` = 비율 유지), 변 = 한 방향 크기, 위쪽 손잡이와 **모서리 바로 바깥** = 회전(`Shift` = 15° 단위). 회전 영역은 그리지 않고 둥근 화살표 커서로 알린다. 기울이기·뒤집기·회전 중심점은 v2.16.0-beta 에서 들어갔다(맨 위 절). 손잡이 크기는 화면 픽셀 기준이라 영상 해상도·확대 배율과 무관하게 일정하다 |
| 변형의 저장 | 레코드의 `transform`(`scaleX`·`scaleY`·`angle`. 돌린 획을 다른 획과 함께 가로·세로 다르게 늘이면 `skewX` 도 쓴다)만 바뀐다. `pathData`·`sourcePoints`·id 는 그대로라 레이어 배정이 유지되고, 실행취소 한 번에 한 조작이다. 스키마는 바뀌지 않았다 — 9개 필드는 원래부터 저장 형식에 있었고 그동안 `left`·`top` 만 썼다 |
| 변형한 획을 다루는 다른 기능 | 투영·정지 화면·편집창 내보내기·어니언 스킨이 모두 `path.set(record.transform)` 으로 그려 같은 모양이다. 올가미·지우개는 오브젝트의 행렬을 거꾸로 적용해 판정하므로 변형한 획도 고르고 자를 수 있다. 외곽선은 본체가 변한 만큼(행렬)을 그대로 따라간다 |
| 변형 상자를 주지 않는 경우 | 선택 도구가 아닐 때, 숨기거나 잠근 레이어의 획. 부분 선택으로 세워 둔 조각은 v2.15.0-beta 부터 변형할 수 있다(위 절). 배율이 0.01~100 배를 벗어나면 저장하지 않고 화면을 되돌린다 |
| `Shift` 판정 | 포인터 이벤트에 실린 `shiftKey` 만 본다. Alt·Ctrl 처럼 오버레이 문서의 키 상태를 기억해 두지 않는다 — 호스트가 Shift 조합(`Shift+2` 등)의 누름을 삼키면 Chromium 이 Shift 뗌을 내보내지 않아, 기억해 둔 값이 눌린 채로 남는다(v2.13.2-beta 에서 고친 Ctrl 고착과 같은 문제). 펜 이벤트에 `shiftKey` 가 실려 오지 않는 환경에서는 펜으로 비율 유지·15° 단위를 쓸 수 없다 |
| Drawing V3 그림자 어댑터 | 크기·회전 전이를 `unsupported-transform` 으로 격리하지 않고, 기준 변형에 대한 아핀 행렬 `M(지금)·M(기준)⁻¹` 로 받는다. 이동뿐인 전이는 종전과 같은 `[1,0,0,1,dx,dy]` 다 |
| 편집창(BEditer) | 같은 런타임이라 변형 상자가 그대로 뜬다. 출력 크기가 그림과 **화면 비율까지 다를 때** 돌린 획은 행렬로 다시 풀어 늘인다(크기 필드에 비율만 곱하면 모양이 틀어진다) |

자동 검사(실제 Fabric 을 띄워 손잡이를 끄는 검사와 픽셀 대조 포함)와, 패키지된 앱을 격리 프로필로 띄워 자동 입력(DevTools 프로토콜의 키·마우스)으로 네 항목을 조작하는 점검으로 확인했다. 사람이 직접 조작하는 실기와 실물 펜 태블릿(특히 펜으로 `Shift` 를 누른 채 끌기)은 미확인이다. 근거는 [작업 기록](../DEVLOG/2026-11-11-drawing-feedback-onion-transform.md).

## 그리기 중 Space (2026-10-06, v2.13.1-beta; Ctrl 예외는 v2.13.2-beta 반영)

| 항목 | 현재 구현 |
|---|---|
| 증상과 원인 | 획을 그은 뒤(오버레이 창이 키보드 포커스를 가진 상태) Space 를 누르면 재생되지 않고 다음 획도 막혔다. 호스트가 `before-input-event` 에서 Space 누름을 삼키면 Chromium 이 짝이 되는 뗌을 내보내지 않아, 메인 창이 Space 를 누른 채로 남았다 |
| Space 누름 | 호스트가 메인 창으로 넘기되 삼키지 않는다(`forwardedSpaceKeyDownKeepsRelease`). 뗌은 넘기고 삼킨다. 메인 창의 탭(재생)·누른 채 끌기(화면 이동) 판정은 그대로다 |
| 오버레이 문서 | 내려온 Space 누름의 기본 동작을 런타임이 막는다(포커스가 남은 팔레트 버튼 누름·스크롤 방지). 키를 넘기는 호스트 안에서, 그리기 입력이 켜져 있고 색상 코드 입력 중이 아닐 때만이다. 편집창은 해당 없음 |
| Alt·Meta+Space | OS 동작으로 넘어가지 않게 계속 삼킨다. 그 뗌은 오지 않으므로 호스트가 짝이 되는 뗌을 곧바로 보낸다. 오버레이에서는 눌렀다 뗀 것으로만 동작한다 |
| Space 를 누른 채 다른 키 | Chromium 은 누름 하나를 삼키면 다음 누름까지 모든 뗌을 버린다. 호스트가 뗌을 못 넘긴 Space 를 기억했다가(`overlaySpaceReleasePending`) 다른 키를 삼키기 직전과 색상 코드 입력 시작 시 그 뗌을 먼저 넘긴다. 그 시점에 Space 누름이 끝난 것으로 처리된다(끌지 않았으면 재생 전환) |
| 다른 키 | 검증된 Ctrl 조합(Alt·Meta 제외)은 위 절처럼 누름을 보존하므로 함께 누른 Space의 실제 뗌도 유지된다. 이 예외와 Space를 제외한 전달 대상 키의 누름은 계속 삼킨다. history 키의 뗌은 호스트에서 중복 처리 방지를 위해 삼키며, Control 뗌은 오버레이 문서가 받아 펜 상태를 복구한다 |

실제 Chromium(숨김 Electron)과 격리 프로필로 띄운 실제 앱에서 DevTools 프로토콜 키 입력으로 확인했다. 실물 키보드·펜 태블릿으로 직접 누르는 확인은 미수행이다. 근거는 [작업 기록](../DEVLOG/2026-10-06-draw-mode-space-release.md).

## 실행과 코멘트 입력 (2026-09-22, v2.12.7-beta)

- 레거시 `drawings` 읽기와 표시 호환성을 유지한다. 기존 데이터의 삭제·자동 변환·이중 저장은 추가하지 않았다.
- C는 영상 재로딩 없이 정지 응답과 최종 프레임을 확인한 뒤 입력을 준비한다. 확대/축소 중에도 일반 클릭으로 마커를 찍고 Space를 누를 때만 화면을 이동한다.
- 화면 중앙의 고정 십자선을 제거하고 실제 포인터에 crosshair 커서를 표시한다. 영상 위 댓글 입력창에도 이미지 붙여넣기·미리보기·삭제를 지원한다.
- 자동 검사·내부 리뷰 결과와 실기 미검증 범위는 [현재 도구 정리 기록](../DEVLOG/2026-09-22-current-drawing-only.md)에 남긴다. 이전 코멘트 개선 근거는 [이전 작업 기록](../DEVLOG/2026-09-22-comment-input-runtime-fix.md)을 참조한다.

>
> - **메타데이터만으로 완결되는 것**(추가·선택·이름·색) → 동작
> - **뷰 상태로 완결되는 것**(표시·잠금) → 동작. 렌더러가 레이어 플래그와 배정으로 **오브젝트 id 집합**을 계산해 오버레이로 밀어 넣고, 오버레이는 그릴 때 그 집합만 본다. 레코드 키 집합이 고정이라 문서에는 쓸 수 없다 — 그래서 집합은 프레임 전환·실행취소·세션 재시작 때마다 다시 적용·재전송된다.
>
>   **주의: fabric 의 `visible`/`selectable`/`evented` 만으로는 모자란다.** 두 가지가 더 있다.
>
>   첫째, 라쏘(획 단위·부분)와 획 지우개는 히트테스트를 쓰지 않고 **씬 스냅샷을 직접 훑는다.** 이 세 경로와 활성 선택 복원(`refreshSelectionInteractionPolicy` 끝)에서 제한된 id 를 함께 걸러야 한다.
>
>   그리고 **전체 지우기(`clear-session`)** 는 씬을 통째로 비우므로 제한된 획이 있으면 선택 삭제 경로로 돌려 남긴다.
>
>   둘째, **집합을 바꾸는 것은 앞으로의 판정만 바꾼다.** 이미 시작했거나 세워 둔 작업은 각자 대상 목록을 쥐고 있어 그대로 커밋된다 — 그리는 중인 획·도형, 끄는 중인 선택(되돌리지 않으면 뒤이은 `object:modified` 가 이동을 저장한다), 부분 선택으로 세워 둔 조각(원본 id 가 아니라 프록시 id 라 선택 필터를 빠져나간다), 지우개 큐(`erasedIds`). `updateDrawingLayerView` 가 네 가지를 모두 물린다. 빠뜨리면 "잠갔는데 바뀌었다" 가 된다
> - **문서를 바꾸는 것**(삭제·순서) → 동작. 오버레이가 그 영상의 **모든 키프레임**에서 오브젝트를 걷거나 랭크대로 다시 세운다. 실행취소는 프레임별 before/after 를 함께 든 **구조 히스토리 한 항목**이라 한 번에 되돌아간다. 한계: 손댄 키프레임의 **획 단위 이력은 사라진다**(구조 조작 공통 — 씬을 갈아 끼우면서 그 씬의 커맨드가 전역 인덱스에서 걷힌다)
>
>   실행취소는 **씬과 레이어 모델을 함께** 되돌려야 한다. 오버레이는 씬만 되돌릴 수 있고 레이어 목록·배정은 렌더러 쪽(`.bframe` 루트)에 있으므로, 조작할 때 모델의 **델타**를 조작의 **짝 id(`commandId`)** 로 기억해 두었다가, 되돌림 응답에 실어 온 같은 id 로 **그때의 현재 상태 위에** 뒤집어 얹는다. 스냅샷을 통째로 덮으면 그 사이에 사용자가 한 다른 편집(레이어 추가·표시 토글 등)이 조용히 사라진다 — 커밋도 같은 이유로 기다린 뒤 **지금** 상태 위에서 다시 계산한다. 짝을 안 지으면 삭제를 되돌렸을 때 그림만 살아나 기준 레이어로 떨어지고, 이동을 되돌렸을 때 겹침 순서만 돌아오고 레이어 목록은 옮긴 채로 남는다. 빈 레이어를 지우거나 이미 순서가 맞아 **씬이 안 바뀌는 경우**에도 표식(`layer-model-marker`)으로 짝 id 를 남긴다 — 없으면 그 다음 `Ctrl+Z` 가 엉뚱한 앞 커맨드를 되돌린다. 오버레이 **팔레트의 되돌리기·다시하기**는 런타임 안에서 바로 처리돼 요청 응답을 타지 않는다(그래서 레이어 조작이 정착하는 동안에는 `layerHistoryBusy` 로 잠근다 — 컨트롤러 큐 밖이라, 정착 전에 눌리면 씬만 먼저 되돌아가고 뒤늦은 커밋이 이미 되돌린 씬 위에 모델을 얹는다). 그래서 레이어 조작을 되돌린 경우에는 짝 id 를 지속화 채널(`layer-history`)로 렌더러에 따로 알린다 — 안 하면 씬만 돌아가고 레이어 목록·배정은 그대로다.
>
>   조작은 씬을 통째로 갈아 끼우고 **전이를 내보내지 않으므로** 지속화 재동기를 따로 요청한다(`persistenceResyncRequired`) — 안 하면 렌더러의 수화 문서가 조작 전 상태로 남아 지운 획이 다시 투영된다. 조작 전체(상태 읽기 → 오버레이 왕복 → 모델 반영)는 한 덩어리로 줄을 세운다: 오버레이 요청만 줄을 세우면 두 단축키가 같은 옛 상태를 읽고 나중 것이 앞선 것의 결과를 덮는다.
>
>   겹침 순서는 **랭크**로 다룬다. 오버레이는 레이어를 모르고 오브젝트별 정수 하나만 받는다. 타임라인 위쪽(`layers[0]`)이 화면에서도 위여야 하므로 배열 인덱스를 뒤집는다(캔버스는 나중 오브젝트를 위에 그린다). 랭크는 표시·잠금 집합과 **같은 경로로 계속** 밀어 넣는다 — 새 획이 그리는 순간 제 층에 들어가지 않으면, 레이어를 옮겨 맞춰 놓은 순서가 다음 획 하나에 다시 어긋난다. 랭크는 **쌍 배열**(`[[id, rank], …]`)로 나른다 — 호스트가 페이로드를 실행할 소스에 객체 리터럴로 끼우는데, 리터럴에서 `"__proto__"` 키는 데이터가 아니라 프로토타입 지정 문법이라 사라진다. 오브젝트 id 를 키로 쓰는 표현은 쓸 수 없다. 레이어를 바꾼 직후에는 랭크 갱신이 오버레이에 닿기 **전에** 획이 커밋될 수 있어(입력을 켠 직후도 같다), 문서 순서가 랭크와 어긋나면 렌더러가 재정렬을 한 번 보내 바로잡는다(**정규화는 히스토리를 남기지 않는다** — 구조 조작으로 처리하면 씬을 갈아 끼우며 그 씬의 획 이력을 걷고 자기를 가장 최근 되돌리기 항목으로 올려, 다음 `Ctrl+Z` 가 방금 그은 획 대신 이 정리를 되돌린다) — 뒤늦은 배정 갱신은 랭크 맵만 바꿀 뿐 이미 커밋된 씬의 순서를 다시 세우지 않는다. 이때 새 획의 자리는 `activeLayerRank` 로 따로 보낸다: 랭크 맵에는 **이미 문서에 있는 id** 만 들어 있어 방금 그은 획은 언제나 빠져 있고, 기본 랭크로 떨어뜨리면 활성 레이어가 무엇이든 늘 기준 레이어 자리에 꽂힌다
>
> 배정은 **새로 나타난 오브젝트 id** 를 보고 그때의 활성 레이어에 붙인다. 단, 획을 자르면(지우개 부분 지우기·올가미 이동) 런타임이 원본을 지우고 **새 id 의 조각**으로 갈아 끼우므로, 같은 알림에서 사라진 오브젝트들이 한 레이어에 모여 있으면 조각은 그 레이어를 물려받는다(여러 레이어가 섞이면 출처를 알 수 없어 활성 레이어로 둔다 — 저장 레코드에 부모 링크가 없다). 그래서 두 가지 규칙이 따라온다: (1) 사라진 배정은 **문서를 처음 심을 때 한 번만** 걷는다 — 실행취소가 되살릴 수 있는 동안 걷으면 그 획이 다른 레이어로 옮겨간 채 저장된다. (2) 영상 전환 렌더는 걷지 않는다 — 그 순간 레이어 상태는 새 파일인데 스토어가 아직 이전 문서를 들고 있을 수 있다.

## 2. 타임라인 표시 대조

### 2.1 레거시 레이어 행 vs 파일럿 투영 행

파일럿 소유 중에는 `getFabricPilotTimelineLayers()`(`app.js`)가 합성 레이어를 만들어 넘긴다. `timeline.js`는 이 객체를 레거시 레이어와 **같은 렌더러**로 그리므로, 공급하지 않은 속성만큼 기능이 빠진다.

| 항목 | 레거시 레이어 | 파일럿 투영 행 |
|---|---|---|
| 행 id | `layer-*` | `fabric-pilot-layer-<레이어 id>` (레이어마다 한 행) |
| 이름 / 색 | 사용자 지정 | 레이어 모델의 이름·색 (`drawingLayersV1`) |
| 키프레임 마커 | ● 채움 / ○ 빈 키프레임 | **동일하게 렌더됨** (`keyframe.isEmpty` 기준) |
| 홀드 구간 | `getKeyframeRanges()` | **동일** (다음 키프레임 직전까지) |
| 마커 클릭 선택 | 가능 | **가능** (시각 확인용) |
| 마커 드래그 이동 | 가능 | **이동 가능** — 파일럿 행은 `timelineKeyframesMovable: true`. 레거시 읽기 전용 투영 행은 이동 불가 |
| `Delete` 삭제 | 가능 | **불가** — `deleteSelectedOrCurrentKeyframes`가 투영 존재 시 `return false` |
| 눈 / 자물쇠 버튼 | 표시 | **CSS로 숨김** (상태 자체는 레이어 모델의 실제 값이다 — 행의 `locked` 는 마커 이동 가능 여부와 별개다) |
| 우클릭 레이어 설정 | 가능 | **핸들러 미등록** |

### 2.2 레거시 `drawings` 데이터의 읽기 전용 투영

과거 레거시로 그린 `drawings`가 있는 `.bframe`을 mpv로 열면, 그 레이어들도 **원래 색·이름 그대로 읽기 전용 행**으로 함께 표시된다(`pilotProjected: true`). 데이터는 보존되며 자동 변환하지 않는다. CSS 마스크에서 `[data-pilot-projected="true"]`로 제외된다.

### 2.3 관련 CSS·선택자

| 대상 | 위치 |
|---|---|
| 마커 | `.keyframe-marker`, `.keyframe-marker-dot`, `.empty` 수식자 |
| 행 | `.drawing-layer-header`, `.drawing-track-row`, `data-layer-id`, `data-pilot-projected` |
| 파일럿 마스크 | `main.css` `body.fabric-drawing-pilot-enabled.mpv-pilot-mode …` |

## 4. 아직 구분해야 할 제한

- F6/F7의 레거시 액션과 키프레임 자체 Delete는 위 표에 표시한 제한이 남아 있다. Shift+3·2의 파일럿 조작이나 선택 획 Delete와 혼동하지 않는다.
- 변형 상자의 회전 중심점은 저장되지 않는다. 선택을 풀거나 다른 것을 고르면 상자의 한가운데로 돌아간다. 크기 조절은 중심점과 무관하게 맞은편 손잡이가 축이다.
- 뒤집기는 팔레트의 버튼으로만 한다(단축키 없음). 손잡이를 반대편으로 넘겨서는 뒤집히지 않는다.
- 펜 이벤트에 `shiftKey` 가 실려 오지 않는 환경에서는 펜으로 비율 유지·15° 단위를 쓸 수 없다(실물 태블릿 미확인). `Ctrl`(기울이기·회전 중심점)은 오버레이 문서가 본 키 상태로 보완하지만 이것도 실물 태블릿에서 확인하지 못했다. 그 보완은 마지막 누름에서 2.5초 안에만 통하므로, 키 반복이 오지 않는 환경이라면 `Ctrl` 을 누르고 2.5초 안에 펜을 대야 한다.
- 패널이 닫힌 상태에서 받는 것은 프레임 조작 7종과 어니언 스킨 토글뿐이다. 레이어 단축키는 종전대로 패널이 열려 있어야 한다.
- 타임라인 투영 행에서의 편집 가능 여부는 §2를 따른다. 단축키 조작 지원과 마커 드래그 지원은 별개다.
- [레이어 이식 기록](../DEVLOG/2026-08-31-레거시-드로잉-단축키-이식.md)의 “16종 완료”는 해당 작업에서 이식한 범위를 뜻하며 모든 레거시 기능의 완료를 의미하지 않는다.

> `drawingsV3` 에는 여전히 레이어가 없다(스키마 불가침). 레이어 모델은 `.bframe` **루트의 `drawingLayersV1`** 에 따로 살고, 오브젝트 id → 레이어 id 배정으로 그림과 이어진다. 그래서 이렇게 갈린다:
>
> - **메타데이터만으로 완결되는 것**(추가·선택·이름·색) → 동작
> - **뷰 상태로 완결되는 것**(표시·잠금) → 동작. 렌더러가 레이어 플래그와 배정으로 **오브젝트 id 집합**을 계산해 오버레이로 밀어 넣고, 오버레이는 그릴 때 그 집합만 본다. 레코드 키 집합이 고정이라 문서에는 쓸 수 없다 — 그래서 집합은 프레임 전환·실행취소·세션 재시작 때마다 다시 적용·재전송된다.
>
>   **주의: fabric 의 `visible`/`selectable`/`evented` 만으로는 모자란다.** 두 가지가 더 있다.
>
>   첫째, 라쏘(획 단위·부분)와 획 지우개는 히트테스트를 쓰지 않고 **씬 스냅샷을 직접 훑는다.** 이 세 경로와 활성 선택 복원(`refreshSelectionInteractionPolicy` 끝)에서 제한된 id 를 함께 걸러야 한다.
>
>   그리고 **전체 지우기(`clear-session`)** 는 씬을 통째로 비우므로 제한된 획이 있으면 선택 삭제 경로로 돌려 남긴다.
>
>   둘째, **집합을 바꾸는 것은 앞으로의 판정만 바꾼다.** 이미 시작했거나 세워 둔 작업은 각자 대상 목록을 쥐고 있어 그대로 커밋된다 — 그리는 중인 획·도형, 끄는 중인 선택(되돌리지 않으면 뒤이은 `object:modified` 가 이동을 저장한다), 부분 선택으로 세워 둔 조각(원본 id 가 아니라 프록시 id 라 선택 필터를 빠져나간다), 지우개 큐(`erasedIds`). `updateDrawingLayerView` 가 네 가지를 모두 물린다. 빠뜨리면 "잠갔는데 바뀌었다" 가 된다
> - **문서를 바꾸는 것**(삭제·순서) → 동작. 오버레이가 그 영상의 **모든 키프레임**에서 오브젝트를 걷거나 랭크대로 다시 세운다. 실행취소는 프레임별 before/after 를 함께 든 **구조 히스토리 한 항목**이라 한 번에 되돌아간다. 한계: 손댄 키프레임의 **획 단위 이력은 사라진다**(구조 조작 공통 — 씬을 갈아 끼우면서 그 씬의 커맨드가 전역 인덱스에서 걷힌다)
>
>   실행취소는 **씬과 레이어 모델을 함께** 되돌려야 한다. 오버레이는 씬만 되돌릴 수 있고 레이어 목록·배정은 렌더러 쪽(`.bframe` 루트)에 있으므로, 조작할 때 모델의 **델타**를 조작의 **짝 id(`commandId`)** 로 기억해 두었다가, 되돌림 응답에 실어 온 같은 id 로 **그때의 현재 상태 위에** 뒤집어 얹는다. 스냅샷을 통째로 덮으면 그 사이에 사용자가 한 다른 편집(레이어 추가·표시 토글 등)이 조용히 사라진다 — 커밋도 같은 이유로 기다린 뒤 **지금** 상태 위에서 다시 계산한다. 짝을 안 지으면 삭제를 되돌렸을 때 그림만 살아나 기준 레이어로 떨어지고, 이동을 되돌렸을 때 겹침 순서만 돌아오고 레이어 목록은 옮긴 채로 남는다. 빈 레이어를 지우거나 이미 순서가 맞아 **씬이 안 바뀌는 경우**에도 표식(`layer-model-marker`)으로 짝 id 를 남긴다 — 없으면 그 다음 `Ctrl+Z` 가 엉뚱한 앞 커맨드를 되돌린다. 오버레이 **팔레트의 되돌리기·다시하기**는 런타임 안에서 바로 처리돼 요청 응답을 타지 않는다(그래서 레이어 조작이 정착하는 동안에는 `layerHistoryBusy` 로 잠근다 — 컨트롤러 큐 밖이라, 정착 전에 눌리면 씬만 먼저 되돌아가고 뒤늦은 커밋이 이미 되돌린 씬 위에 모델을 얹는다). 그래서 레이어 조작을 되돌린 경우에는 짝 id 를 지속화 채널(`layer-history`)로 렌더러에 따로 알린다 — 안 하면 씬만 돌아가고 레이어 목록·배정은 그대로다.
>
>   조작은 씬을 통째로 갈아 끼우고 **전이를 내보내지 않으므로** 지속화 재동기를 따로 요청한다(`persistenceResyncRequired`) — 안 하면 렌더러의 수화 문서가 조작 전 상태로 남아 지운 획이 다시 투영된다. 조작 전체(상태 읽기 → 오버레이 왕복 → 모델 반영)는 한 덩어리로 줄을 세운다: 오버레이 요청만 줄을 세우면 두 단축키가 같은 옛 상태를 읽고 나중 것이 앞선 것의 결과를 덮는다.
>
>   겹침 순서는 **랭크**로 다룬다. 오버레이는 레이어를 모르고 오브젝트별 정수 하나만 받는다. 타임라인 위쪽(`layers[0]`)이 화면에서도 위여야 하므로 배열 인덱스를 뒤집는다(캔버스는 나중 오브젝트를 위에 그린다). 랭크는 표시·잠금 집합과 **같은 경로로 계속** 밀어 넣는다 — 새 획이 그리는 순간 제 층에 들어가지 않으면, 레이어를 옮겨 맞춰 놓은 순서가 다음 획 하나에 다시 어긋난다. 랭크는 **쌍 배열**(`[[id, rank], …]`)로 나른다 — 호스트가 페이로드를 실행할 소스에 객체 리터럴로 끼우는데, 리터럴에서 `"__proto__"` 키는 데이터가 아니라 프로토타입 지정 문법이라 사라진다. 오브젝트 id 를 키로 쓰는 표현은 쓸 수 없다. 레이어를 바꾼 직후에는 랭크 갱신이 오버레이에 닿기 **전에** 획이 커밋될 수 있어(입력을 켠 직후도 같다), 문서 순서가 랭크와 어긋나면 렌더러가 재정렬을 한 번 보내 바로잡는다(**정규화는 히스토리를 남기지 않는다** — 구조 조작으로 처리하면 씬을 갈아 끼우며 그 씬의 획 이력을 걷고 자기를 가장 최근 되돌리기 항목으로 올려, 다음 `Ctrl+Z` 가 방금 그은 획 대신 이 정리를 되돌린다) — 뒤늦은 배정 갱신은 랭크 맵만 바꿀 뿐 이미 커밋된 씬의 순서를 다시 세우지 않는다. 이때 새 획의 자리는 `activeLayerRank` 로 따로 보낸다: 랭크 맵에는 **이미 문서에 있는 id** 만 들어 있어 방금 그은 획은 언제나 빠져 있고, 기본 랭크로 떨어뜨리면 활성 레이어가 무엇이든 늘 기준 레이어 자리에 꽂힌다
>
> 배정은 **새로 나타난 오브젝트 id** 를 보고 그때의 활성 레이어에 붙인다. 단, 획을 자르면(지우개 부분 지우기·올가미 이동) 런타임이 원본을 지우고 **새 id 의 조각**으로 갈아 끼우므로, 같은 알림에서 사라진 오브젝트들이 한 레이어에 모여 있으면 조각은 그 레이어를 물려받는다(여러 레이어가 섞이면 출처를 알 수 없어 활성 레이어로 둔다 — 저장 레코드에 부모 링크가 없다). 그래서 두 가지 규칙이 따라온다: (1) 사라진 배정은 **문서를 처음 심을 때 한 번만** 걷는다 — 실행취소가 되살릴 수 있는 동안 걷으면 그 획이 다른 레이어로 옮겨간 채 저장된다. (2) 영상 전환 렌더는 걷지 않는다 — 그 순간 레이어 상태는 새 파일인데 스토어가 아직 이전 문서를 들고 있을 수 있다.

## 2. 타임라인 표시 대조

### 2.1 레거시 레이어 행 vs 파일럿 투영 행

파일럿 소유 중에는 `getFabricPilotTimelineLayers()`(`app.js`)가 합성 레이어를 만들어 넘긴다. `timeline.js`는 이 객체를 레거시 레이어와 **같은 렌더러**로 그리므로, 공급하지 않은 속성만큼 기능이 빠진다.

| 항목 | 레거시 레이어 | 파일럿 투영 행 |
|---|---|---|
| 행 id | `layer-*` | `fabric-pilot-layer-<레이어 id>` (레이어마다 한 행) |
| 이름 / 색 | 사용자 지정 | 레이어 모델의 이름·색 (`drawingLayersV1`) |
| 키프레임 마커 | ● 채움 / ○ 빈 키프레임 | **동일하게 렌더됨** (`keyframe.isEmpty` 기준) |
| 홀드 구간 | `getKeyframeRanges()` | **동일** (다음 키프레임 직전까지) |
| 마커 클릭 선택 | 가능 | **가능** (시각 확인용) |
| 마커 드래그 이동 | 가능 | **이동 가능** — 파일럿 행은 `timelineKeyframesMovable: true`. 레거시 읽기 전용 투영 행은 이동 불가 |
| `Delete` 삭제 | 가능 | **불가** — `deleteSelectedOrCurrentKeyframes`가 투영 존재 시 `return false` |
| 눈 / 자물쇠 버튼 | 표시 | **CSS로 숨김** (상태 자체는 레이어 모델의 실제 값이다 — 행의 `locked` 는 마커 이동 가능 여부와 별개다) |
| 우클릭 레이어 설정 | 가능 | **핸들러 미등록** |

### 2.2 레거시 `drawings` 데이터의 읽기 전용 투영

과거 레거시로 그린 `drawings`가 있는 `.bframe`을 mpv로 열면, 그 레이어들도 **원래 색·이름 그대로 읽기 전용 행**으로 함께 표시된다(`pilotProjected: true`). 데이터는 보존되며 자동 변환하지 않는다. CSS 마스크에서 `[data-pilot-projected="true"]`로 제외된다.

### 2.3 관련 CSS·선택자

| 대상 | 위치 |
|---|---|
| 마커 | `.keyframe-marker`, `.keyframe-marker-dot`, `.empty` 수식자 |
| 행 | `.drawing-layer-header`, `.drawing-track-row`, `data-layer-id`, `data-pilot-projected` |
| 파일럿 마스크 | `main.css` `body.fabric-drawing-pilot-enabled.mpv-pilot-mode …` |

## 4. 아직 구분해야 할 제한

- F6/F7의 레거시 액션과 키프레임 자체 Delete는 위 표에 표시한 제한이 남아 있다. Shift+3·2의 파일럿 조작이나 선택 획 Delete와 혼동하지 않는다.
- 어니언 스킨은 파일럿 미구현이다. 기존의 “캔버스가 영상을 가림” 설명만으로 현재 원인을 단정하지 않는다.
- 타임라인 투영 행에서의 편집 가능 여부는 §2를 따른다. 단축키 조작 지원과 마커 드래그 지원은 별개다.
- [레이어 이식 기록](../DEVLOG/2026-08-31-레거시-드로잉-단축키-이식.md)의 “16종 완료”는 해당 작업에서 이식한 범위를 뜻하며 모든 레거시 기능의 완료를 의미하지 않는다.

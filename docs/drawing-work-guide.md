# 드로잉 작업 규칙

작업 전 [현재 기능표](drawing-keyframe-features.md)와 [개발 가이드](development-guide.md)의 테스트 항목을 읽는다.

## 데이터와 책임

- 현재 작성 도구는 Fabric 하나이며 `drawingsV3`를 사용한다. 재생 엔진과 드로잉 표면의 준비 상태를 구분한다. 구형 `drawings`는 표시·읽기·저장 호환용으로 보존하며 임의로 이중 저장·자동 변환하지 않는다. 구형 작성 팔레트·포인터 입력 엔진을 다시 연결하지 않는다.
- 레이어 목록·활성 레이어·오브젝트 배정은 `.bframe` 루트의 `drawingLayersV1`에 있다. `drawingsV3` 레코드 안에 레이어 필드를 추가하지 않는다.
- 렌더러가 레이어에서 숨김·잠금 id 집합과 랭크를 계산하고 오버레이는 적용한다. 레이어 모델과 그림 문서의 성공·실패·실행취소를 함께 처리한다.
- 액션 id로 단축키를 판정한다. `userSettings.matchShortcut`과 파일럿 라우팅을 확인하여 재지정한 키도 동작하게 한다.
- 레코드의 `transform`은 9개 필드를 모두 쓴다(변형 상자의 크기·회전·기울이기·뒤집기). 획의 자리·모양을 다루는 코드는 `left`·`top`만 더하지 말고 행렬로 다룬다. 외곽선 짝은 본체와 중심이 달라 값을 베끼면 어긋나므로 본체가 변한 만큼(행렬)을 따라가게 한다.
- `transform`의 배율은 양수로, 뒤집힘은 `flipX`·`flipY`로 적는다. 행렬을 분해해 적을 때(`qrDecompose`)는 뒤집힘이 음수 세로 배율로 나오므로 `storedTransformFromDecomposition`을 거친다. 음수 배율을 그대로 적으면 `path.set(record.transform)`이 배율 다음에 레코드의 `flipY: false`를 덮어 뒤집히지 않은 모양으로 그려진다.
- 회전 중심점처럼 문서에 없는 화면 상태는 fabric 오브젝트에 묶어 두고, 씬을 다시 세울 때(저장 뒤의 재선택) 명시적으로 옮긴다. 레코드에 필드를 더해 저장하지 않는다. 그림에 붙어 다녀야 하는 자리는 상자의 비율이 아니라 **오브젝트 자신의 좌표**로 든다(비율은 기울이면 그림에서 어긋난다). 선택 알림(`selection:*`)은 같은 묶음 오브젝트를 고쳐 쓰는 경우(Shift+클릭)에도 오므로 "오브젝트가 같다"를 "선택이 같다"로 읽지 않는다.
- 펜·터치용 키 상태 보완(문서가 본 Ctrl·Alt)을 새 조작에 쓸 때는, 그 표시가 남았을 때 무엇이 막히는지부터 본다. 탭 한 번을 통째로 가져가는 조작이라면 방금 눌린 것만 믿는다(`isTransformCtrlActive`).
- 그리기 패널이 닫힌 상태(passive)에는 세션 id가 없다. 그 상태에서 문서를 바꾸는 요청은 영상 정체로 맞추고, 실행취소는 그 조작의 표식으로만 되돌린다. 패널을 열어 한 편집을 닫힌 상태의 단축키가 되돌리게 하지 않는다.

## 변경 전 점검

| 경계 | 확인할 사항 |
|---|---|
| 문서 | 모든 키프레임, 홀드 중 임시 씬, 외곽선 짝 id |
| 입력 | 진행 중인 획·도형·선택·변형·라쏘 조각·지우개 큐 |
| 화면 | 활성 캔버스, 숨김·잠금 상태, 선택 복원, 타임라인 투영 |
| 비동기 처리 | 오버레이 응답과 렌더러 커밋 사이, 영상·세션 전환, 지연된 랭크·저장 응답 |
| 복원 | 전역 편집 순서, 레이어 배정, 다른 편집과의 병합, redo 무효화 |

플래그를 바꿔도 이미 시작한 작업의 대상 목록은 남는다. 조작 전 진행 중인 작업을 안전하게 마무리하거나 취소한다. Fabric의 visible/selectable/evented만 바꾸는 것으로 끝내지 말고 씬 스냅샷을 직접 훑는 선택·지우개 경로도 확인한다.

## 실행취소와 동시 편집

- 그림과 레이어 모델이 함께 되돌아가도록 짝 id와 변경분을 연결한다. 전체 모델 스냅샷으로 덮어써 그 사이 다른 편집을 지우지 않는다.
- 레이어 이동 위치는 숫자 인덱스만 저장하지 않고 이웃 레이어의 정체를 기준으로 복원한다.
- 삭제·재배열은 모든 관련 키프레임을 다룬다. 새 획도 활성 레이어의 순서를 따라야 한다.
- 정규화는 사용자의 편집 이력을 대신 차지하지 않게 한다. 구조 조작에서 영향받는 획 이력이 정리되는 범위와 redo 처리를 확인한다.
- 실행취소로 되살릴 수 있는 오브젝트의 레이어 배정을 너무 일찍 지우지 않는다.
- 응답을 기다리는 조작이 "언제 한 일인가"는 응답이 온 때가 아니라 **요청한 때**의 값(전역 히스토리 리비전 등)으로 적는다. 응답 때 읽으면, 기다리는 사이에 한 다른 작업보다 먼저 한 조작이 마지막으로 한 일로 보여 실행취소 순서가 뒤집힌다.

## 표시·저장·검증

- `requestRenderAll()`은 예약이다. 저장 성공과 실제 화면 표시를 같은 것으로 보지 말고 재진입·프레임 이동·실행취소 후 표시를 확인한다.
- IPC 응답은 요청 당시 영상·세션·토큰과 맞는지 검증한다. pointerup과 lostpointercapture의 순서, 빠른 연속 입력, 지연·실패 응답을 포함한다.
- 원본 런타임 변경 후 `npm run bundle:mpv-fabric-overlay`를 실행하고 생성 번들을 함께 반영한다.
- 관련 자동 테스트 외에 저장 후 재열기, 다른 프레임에서 실행취소, 레이어 숨김·잠금 중 입력, 동시 편집을 작업 범위에 맞게 확인한다.
- 변형·선택을 검사할 때는 **가는 가로선**(높이가 선택 상자의 여백보다 작은 획)과 **손잡이를 한가운데에서 벗어나 잡는 경우**를 포함한다. fabric 7.4.0 의 크기 손잡이는 포인터의 절대 위치를 크기로 바꾸는데, 세로 방향 여백 계산이 틀려 있고 잡은 자리의 어긋남도 보지 않는다. 런타임이 `resolveScalePointer`로 대신 계산한다. 대각선 획의 손잡이 한가운데만 끌어 보면 드러나지 않는다(v2.14.0-beta 가 그렇게 나갔다).
- 실제 Fabric 하네스로 포인터 조작을 검사할 때는 조작 사이에 한 박자 쉰다. 선택 제스처는 손을 뗀 뒤에 정리되므로, 쉬지 않고 이어 보내면 앞 제스처가 남아 런타임이 다음 누르기를 건너뛰고 실제 사용자가 타지 않는 경로가 통과한다.
- 변형 상자에 손잡이나 보조키 조작을 더할 때는 **상자 한가운데를 잡아 옮기기**와 **빈 곳을 눌러 선택 풀기**가 그대로인지 본다. 상자 안에 잡히는 것을 늘 띄워 두면 가장 흔한 조작(옮기기)을 가로챈다. 모서리 바깥의 회전 영역처럼 보이지 않는 손잡이가 새 조작의 자리를 막지 않는지도 본다.
- Fabric의 손잡이 계산(크기·기울이기·커서)은 화면 축이나 오브젝트 한가운데를 기준으로 삼는 곳이 있다. 변형을 검사할 때는 **돌려 둔 획**, **길쭉한 획**, **이미 뒤집거나 기울인 획**, **여러 획을 고른 묶음**을 포함하고, 저장된 값이 끄는 동안 화면에 보인 행렬과 같은지를 견준다.

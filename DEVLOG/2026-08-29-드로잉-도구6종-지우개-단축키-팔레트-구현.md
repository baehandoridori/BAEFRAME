## §3.3 도형 렌더 스모크 검증 결과 — **분기 없음, 기본 `nonzero`**

계획서가 착수 전 필수로 지정한 검증이다. 결과가 이후 라운드의 전제가 되므로 기록한다.

`perfect-freehand`의 `getStroke`는 열린 폴리라인을 가정하고 좌/우 오프셋을 하나의 닫힌 윤곽으로
잇는다. 사각형·원처럼 **시작점 = 끝점인 닫힌 루프**에서 내부가 `nonzero` fill 로 메워질 위험이 있어,
4개 도형의 `pathData` 를 실제로 뽑아 SVG 로 렌더해 눈으로 확인했다.

| 도형 | 표본 | 윤곽점 | `pathData` |
|---|---|---|---|
| line | 25 | 90 | 2,764자 |
| rect | 97 | 234 | 4,885자 |
| circle | 129 | 294 | 9,033자 |
| arrow | 97 | 308 | 9,650자 |

**결과: `nonzero` 4종 모두 정상.** `getStroke` 가 바깥 고리와 안쪽 고리를 **반대 감기 방향으로**
뽑아내므로 사각형·원의 속이 저절로 비어 나온다. 화살촉도 선명했다.

대안으로 만들어 본 `evenodd` 는 **더 나쁘다** — 사각형 모서리에 구멍이 나고, 축을 되짚는 화살표는
자기 교차 구간이 상쇄되어 알아볼 수 없게 뭉개진다.

→ 계획서 §3.3 분기표의 첫 번째 행을 택했다. **`renderGeometry` 를 싣지 않는다.**
`SHAPE_EDGE_SEGMENTS` 는 24, `SHAPE_ELLIPSE_SEGMENTS` 는 128 그대로다.

## 작업 3 — 도구 6종

### 설계의 핵심

도형은 **"미리 계산된 경로를 따라 그은 획"** 으로 저장한다. 중심선을 표본으로 만들어 브러시와
같은 `createStrokePathData()` 에 통과시키므로 `drawingsV3` 스키마가 한 글자도 바뀌지 않는다.
그 결과 이동·크기조절·선택·부분지우개·실행취소·협업 동기화·지속화가 **새 코드 없이** 도형에 적용된다.

- 직선·사각형: 24분할 보간
- 원: 드래그 사각형에 내접하는 128분할 타원. 시작점은 곡선 위가 아니라 버린다(중심에서 뻗은 꼬리 방지)
- 화살표: 축과 촉을 `start→end→barbA→end→barbB` 로 되짚어 **하나의** 폴리라인으로 만든다.
  레코드를 둘로 쪼개면 실행취소·선택·이동이 축과 촉을 따로 다루게 되어 더 나쁘다

### 2종 가정 정규화 12곳 교체

`shared/fabric-drawing-tools.js` 를 신설해 런타임과 호스트가 같은 도구 목록을 보게 했다.
컨트롤러는 브라우저 네이티브 ES 모듈이라 CommonJS 를 `import` 할 수 없어 리터럴을 두고,
파리티 테스트가 두 목록을 대조한다(`fabric-drawing-limits.js` ↔ 지속화 스토어와 같은 구조).

특히 위험했던 3곳:

| 지점 | 교체하지 않았을 때의 피해 |
|---|---|
| `setDrawingInput` 비활성 경로 | 펜으로 그리다 그리기 모드를 끄면 도구가 `brush` 로 접힌다 |
| 호스트 disable 응답 | 새 도구가 실리지 않아 컨트롤러가 도구를 잃는다 |
| 컨트롤러 `desiredTool` 복원 | 재진입 시 도구가 초기화된다 |

### 제스처에서 순서가 결정적인 지점

- **pointerup 에서 커밋이 캡처 해제보다 먼저다.** `releasePointerCapture` 가 동기적으로
  `lostpointercapture` 를 발생시킬 수 있고, 그 이벤트가 취소 경로로 흘러 제스처를 먼저 비우면
  뒤이은 커밋이 `no-shape-gesture` 를 반환해 **도형이 씬에 들어가지 않는다.**
- **`onDocumentPointerUp` 은 취소가 아니라 커밋 위임 경로다.** 포인터 캡처가 듣지 않는 환경에서
  제스처를 회수하는 자리이므로, 여기에 취소를 넣으면 도형이 매번 조용히 사라진다.
- **재진입 가드 2곳에 `shapeGesture` 를 넣었다.** 도형 드래그 중 두 번째 포인터의 pointerdown 이
  들어오면 프레임 확정 왕복이 열려 씬이 바뀌고, 진행 중이던 도형이 **다른 키프레임으로 들어간다.**

### 계획서에서 벗어난 판단 1건

`releaseSurfaceResources` 에도 `cancelShapeGesture()` 를 넣었다. 계획서는 `setDrawingInput` 만
지정했으나 두 경로가 같은 4줄 블록을 공유하고, 표면 해제 시 남은 제스처가 파괴된 캔버스를 가리키는
미리보기 오브젝트를 들고 다음 세션으로 샌다.

## 작업 4 — 지우개 도구와 지우개 방식

### 픽셀 모드가 리본 폴리곤인 이유

초안은 "지우개 스윕 사각형들의 **합집합 폴리곤**"을 부분 삭제 경로에 넘기라고 했으나
**저장소에 폴리곤 불리언 유니온이 없다**(`unionBounds` 는 바운딩 박스 합집합일 뿐이다).

대신 지나간 경로 자체를 반경만큼 좌/우로 부풀린 **닫힌 단순 폴리곤(리본)** 을 만들어
기존 `finalizePartialSelectionPolygon` → `commitPendingLassoDelete` 경로에 한 번에 넘긴다.
분할 엔진·저장 스키마·실행취소 1건 계약이 모두 그대로다.

되짚기·정지 구간이 그대로 남으면 리본이 자기 자신과 교차해 `validateSimpleContour` 를 통과하지
못하므로, 라쏘와 같은 방식(`simplifyClosedPolygon`)으로 먼저 줄인다.

### 확정한 동작

- **Ctrl 임시 지우개는 항상 획 단위다.** modifier 제스처가 팔레트 상태에 따라 달라지면
  사용자가 예측할 수 없다. 브러시뿐 아니라 펜에서도 그대로 동작한다.
- **모드는 제스처 시작 시점에 래치한다.** 드래그 도중 방식을 바꿔도 한 제스처 안에서
  커밋 방식이 갈리지 않는다.
- **기본값은 획 단위.** 레거시 HTML 기본은 픽셀이지만, 파일럿의 Ctrl 임시 지우개가 이미
  획 단위라 모드 전환 시 놀라지 않는 쪽을 골랐다.
- 조각이 생기지 않는 경우(리본이 획을 통째로 덮음, 폴리곤이 너무 작음)에는 획 단위 삭제로
  떨어져 "그었는데 아무것도 안 지워졌다"를 겪지 않게 한다.

### 남긴 한계 — 픽셀 모드의 커밋 영역은 스윕의 **근사**다

코덱스 리뷰 2·4·7·8차가 모두 이 지점을 파고들었다. 사실 관계를 정확히 남긴다.

- **히트 판정**은 이동 구간마다 만든 스윕 사각형들의 합집합으로 한다.
- **커밋**은 그 합집합을 근사한 **단순 폴리곤 하나**로 한다.
- 저장소에 **폴리곤 불리언 유니온이 없다**(`unionBounds` 는 바운딩 박스 합집합일 뿐이다).
  `finalizePartialSelectionPolygon` 은 한 번에 폴리곤 하나만 스테이징하고,
  두 번 부르면 앞의 스테이징이 교체되므로 여러 폴리곤을 하나의 커밋으로 합칠 수 없다.

그래서 근사를 단계적으로 정확하게 만들었다.

| 라운드 | 고친 것 |
|---|---|
| 2 | 볼록 껍질 폐기 → 축을 따르는 스크럽만 복도로 되살리고, 그 밖은 아무것도 지우지 않는다 |
| 2 | 리본 끝을 반경만큼 연장해 스윕의 끝 캡과 맞춤 |
| 4 | 복도를 **연장하지 않은** 척추에서 만들어 반경을 두 번 더하던 것을 바로잡음 |
| 7 | 꺾임 바깥 모서리에 마이터 조인을 넣어 스윕 합집합의 모서리를 그대로 덮음 |

**남은 차이**: 꺾임 **안쪽** 모서리. 스윕 사각형 두 개는 꼭짓점 주변 `2r × 2r` 를 모두
덮지만, 리본의 안쪽은 평균 법선 한 점(`0.707r`)으로 접힌다. 안쪽에도 온전한 조인을 넣으면
오프셋이 서로를 가로질러 단순 폴리곤이 못 되고, 그러면 **커밋이 통째로 무산돼 꺾인 드래그가
아무것도 지우지 못한다**(기하 프로브로 실측). 그래서 바깥쪽에만 넣었다.

이 차이가 만들던 증상은 "드래그 중 숨었던 획이 손을 떼면 되살아난다"였다.
정확히 일치시킬 수 없다면 **숨기지 않는 편이 정직하므로**, 픽셀 모드는 드래그 중 아무것도
숨기지 않고 손을 뗄 때 잘린 결과만 보여 준다(8차). 획 단위 모드는 미리보기가 커밋과
정확히 일치하므로 그대로 둔다.

**후속 라운드에서 할 것**: 폴리곤 불리언 유니온을 들여오거나 직접 구현해,
커밋 폴리곤을 히트 판정과 같은 합집합으로 만든다. 그때 이 절의 근사는 전부 걷어낸다.

## 작업 5 — `[` `]` 브러시 크기

### 배선 위치

**컨트롤러의 `routeKeydown()`** 이다. 방화벽 술어(`shouldBlockFabricDrawingLegacyShortcut`)에
넣으면 falsy 를 돌려줘 키다운 핸들러가 계속 진행하고, 레거시 브러시 크기까지 함께 바뀐다.

```
app.js (매처 주입) → controller.routeKeydown() → sendBrushSize()
  → preload  mpvUpdateOverlayDrawingBrush
    → ipc-handlers  'mpv:update-overlay-drawing-brush'
      → host.updateDrawingBrush()  (토큰·범위 검증)
        → runtime.updateDrawingBrush() → setBrushSize()
```

### 빠뜨리면 조용히 죽는 지점

**`brushRevision` 리셋 6곳.** 특히 `setDrawingInput` enable 성공 시 `0` 리셋을 빠뜨리면,
첫 세션에서 `[`/`]` 를 12번 누른 뒤 새 세션이 `brushRevision = 0` 으로 시작해
`0 <= 12` 로 **앱을 재시작할 때까지 전부 stale 거부된다.** 회귀 테스트를 넣었다.

### 판정은 액션 id 기준

사용자가 `[`/`]` 를 다른 키로 재지정해도 따라가야 하므로 `userSettings.matchShortcut('brushSizeUp'|'brushSizeDown')`
기반 매처를 app.js 가 주입한다. chord 로 재지정한 경우를 위해 modifier 가드 허용 목록에도 넣었다.

### 계획서에서 벗어난 판단 1건

계획서는 공개 API 에 `setBrushSizeShortcutMatcher` 를 노출하라고 했으나, 형제 매처
(`matchesSelectionShortcut`)가 **생성자 옵션 하나로만** 주입되는 구조여서 같은 방식으로 통일했다.
setter 를 노출하면 아무도 부르지 않는 공개 메서드가 남는다.

### HUD

좌표 없이 크기가 바뀌는 경로이므로 레거시와 같이 크기 HUD 를 **화면 중앙**에 700ms 띄운다.
그러지 않으면 팔레트 숫자만 바뀌어 굵기 변화가 눈에 보이지 않는다.
Alt 제스처가 시작되면 그 타이머를 회수해, 늦게 발화한 타이머가 제스처 HUD 를 지우지 않게 한다.

## 작업 6 — 팔레트 재구성

### 목업으로 확정한 구성 (§0.3)

| 항목 | 확정 |
|---|---|
| 도구 줄 | **한 줄 5개** — 브러시·펜·지우개·**도형▾**·선택. `repeat(5, minmax(0,1fr))` gap 3px |
| 도형 | 버튼 1개 + 드롭다운 4종. 버튼에 마지막에 쓴 도형이 남고 우하단 4px 삼각형으로 예고 |
| 버튼 라벨 | **아이콘 전용.** 이름은 `title`·`aria-label` 로 |
| 아이콘 | `renderer/index.html` 의 레거시 SVG 재사용. 신규 제작 없음 |

**계획서 §6.3 의 4열 그리드 처방은 폐기했다.** 도형이 드롭다운으로 접혀 도구가 5개가 되므로
한 줄에 들어가고, 4×2 그리드가 레이아웃 테스트를 깨뜨리던 문제가 애초에 발생하지 않는다.

`minmax(0, 1fr)` 은 그대로 필요하다 — `1fr` 만 쓰면 버튼의 `min-width: 40px` 이 트랙 하한이 되어
팔레트를 넘친다.

**도형 도구 상태를 새로 만들지 않았다.** 런타임의 도구 값은 `line`/`rect`/`circle`/`arrow` 그대로이고,
팔레트가 "그 4종 중 활성인 것"으로 **표시만** 묶는다. 드롭다운 선택은 기존
`updateLocalDrawingTool('rect')` 를 그대로 부른다.

### 레이아웃 테스트 갱신 2건

1. **도구 줄 최소 폭 하한을 39.5px → 28.5px 로 낮췄다** (도구 줄 액션에만 적용).
   실측: 220px 팔레트에서 약 37px, 190px 에서 **29px**. 아이콘 전용 버튼이므로 설계대로다.
   나머지 버튼과 접기 버튼의 하한은 그대로다.
2. **`brush-settings` 를 측정 목록에서 뺐다.** 이 하네스는 `select` 도구로 입력을 켜는데,
   맥락 표시가 브러시 설정 섹션을 숨기므로 박스가 0이 된다 — 의도된 동작이다.
   대신 섹션 표시 여부(`tools`·`actions` 보임 / `brush`·`eraser` 숨김)를 직접 단언한다.

### 상시 요약 줄과 최근 색

`brushControls.summary` 는 설정 **버튼의 자식**이고 `sizePreview` 는 패널 안에 있다.
`appendChild` 는 노드를 **이동**시키므로 이들을 새 섹션으로 옮기면 원래 자리에서 사라진다.
상시 노출용 요소를 **새로 만들었고**, 회귀 테스트로 `summary` 가 설정 버튼의 자식으로 남아 있는지 고정했다.

최근 색은 색상 팔레트 **아래**에 붙였다(목업 확정). 패널 조립부에서 직접 `appendChild` 하므로
`insertBefore` 가 필요 없다 — 단위 테스트의 가짜 DOM 은 `insertBefore` 를 구현하지 않는다.

# 이전 버전 리뷰 보기 — 아이디어와 목업

작성일: 2026-09-08

상태: 디자인 탐색 초안. 사용자가 이어받기 필요성과 수정 반영 확인이라는 목적을 확정했다. 리뷰 기능은 목업 단계이며 실제 앱 기능은 수정하지 않는다. 같은 대화에서 요청한 전혜림 팀원 추가는 소스에 별도로 반영한다.

## 사용자가 하려는 일

같은 영상의 v1, v2, v3 리뷰를 현재 버전 옆에서 읽고 수정 사항이 반영되었는지 확인한다. 보고 싶은 버전을 선택하고, 현재 리뷰와 이전 리뷰를 혼동하지 않는 화면을 찾는다.

이번 결과물은 세 가지 배치를 비교하는 인터랙티브 목업이다. 실제 영상, 리뷰 파일, 협업 데이터와 연결하지 않고 가상 예시만 사용한다.

## 현재 코드에서 확인한 기능

- 댓글 필터의 작은 기록 아이콘으로 다른 버전 하나를 선택할 수 있다. `renderer/index.html:1148`, `renderer/scripts/app.js:3613`.
- 선택한 버전의 댓글은 현재 목록 맨 아래 읽기 전용 영역에 붙는다. 작성자·텍스트·시간만 표시하며, 답글·첨부·해결 상태는 이 경로에서 생략된다. `renderer/scripts/app.js:13334`.
- 상단 버전 메뉴의 기존 `피드백 가져오기`는 다른 동작이다. 댓글을 새 ID로 복사하여 현재 `.bframe`에 저장한다. `renderer/scripts/modules/version-dropdown.js:413`, `renderer/scripts/app.js:11029`.
- 기존 어두운 화면, 노란색 강조, 오른쪽 댓글 패널을 목업의 기준으로 삼는다. `renderer/styles/main.css:10`.

## 권장 방향

기능 이름은 **이전 리뷰 확인**으로 제안한다. 원문을 읽는 참조와, 이번 버전에서 반영 여부를 확인하는 목록을 함께 제공한다. 버전을 선택하는 것만으로 할 일이 생기지 않으며 사용자가 명시적으로 이어받는다.

기본 배치는 오른쪽 패널 안의 **분리 보기**다. 위쪽에는 현재 리뷰, 아래쪽에는 선택한 이전 버전 리뷰를 둔다. 영상 크기와 익숙한 화면 배치를 최대한 유지하면서 두 종류를 동시에 읽을 수 있다. 실제 구현에서는 구역 접기 또는 높이 조절을 검토한다.

| 방식 | 잘 맞는 상황 | 비용과 한계 | 제안 위치 |
| --- | --- | --- | --- |
| 분리 보기 | 이전 지적 사항을 보며 현재 영상을 확인 | 리뷰가 많으면 두 구역의 스크롤 공간이 줄어듦 | 기본값 |
| 합쳐 보기 | 같은 시간대의 현재·과거 의견을 연속으로 읽기 | 버전이 많을수록 목록이 길고 출처를 혼동하기 쉬움 | 보기 전환 |
| 팝업 | 필요한 위치에 참고 목록을 잠시 두기 | 영상이나 조작부를 가릴 수 있음 | 보조 모드 |
| 운영체제의 별도 창 | 두 번째 모니터에서 지속적으로 확인 | 창 간 선택·재생 상태 공유와 포커스 관리 필요 | 후속 단계 |

목업의 팝업은 앱 화면 안의 이동 가능한 작은 패널이다. 운영체제의 별도 창 기능을 구현했다고 해석하지 않는다.

## 목업에 담을 흐름

1. 현재 v4 영상을 연 상태에서 `이전 리뷰`의 버전 선택을 연다.
2. v3를 기본 선택한다. v1·v2를 추가하거나 모두 해제할 수 있다. 각 선택 항목에 파일명과 리뷰 수를 표시한다.
3. 모든 이전 댓글에 `v3 · 이전`처럼 출처를 반복 표시한다. 제목, 문자 배지, 보조색을 함께 사용하고 본문을 흐리게 만들지 않는다.
4. 분리·합쳐·팝업 보기로 바꿔도 선택한 버전과 현재 영상 v4를 유지한다.
5. 이전 댓글의 시간 버튼을 누르면 현재 영상의 같은 시간으로 이동하는 사용감을 시뮬레이션한다. 버튼의 접근 가능한 이름이나 인접 문구는 `현재 v4의 00:04:12로 이동`처럼 목적지를 명시하고, 원본 시간과 현재 버전의 재생 상태를 남긴다.
6. 답글을 펼쳐 읽고 미해결만 볼 수 있다. 과거 상태는 `v3에서 해결됨`처럼 출처를 포함하고, 통합 필터에는 각 버전의 원본 상태 기준임을 표시한다. 현재 버전에서 검수 완료했다는 뜻이 아니다.
7. 선택한 버전이 없으면 선택을 안내한다. 현재 영상 길이 밖의 코멘트는 이동할 수 없음을 표시한다.
8. 선택한 버전의 아직 이어받지 않은 미완료 항목을 `미해결 N건 이어받기`로 추가한다. 개별 리뷰의 `확인 항목으로 추가`로 완료된 원본도 다시 검수할 수 있다.
9. `이번 버전 확인` 목록에서 각 항목을 **확인 전 / 반영 확인 / 추가 수정**으로 표시한다. 원본의 작성자·내용·버전·원래 시간은 출처로 남기고, 원본 해결 상태는 바꾸지 않는다.
10. 이어받은 항목은 참조할 버전을 해제하거나 보기 모드를 바꿔도 유지된다. 같은 원본을 현재 버전에 중복 추가하지 않는다. `이어받기 취소`는 이번 버전의 확인 목록에서만 제거한다.

## 꼭 구분해야 하는 의미

- **참고**: 이전 원문을 읽는다. 현재 `.bframe`에 복제 댓글을 저장하지 않는다.
- **이어받기**: 이전 미해결 항목을 현재 버전에서 다시 처리한다. 현 버전에서의 처리 여부, 원본과의 연결, 중복 방지 규칙이 별도로 필요하다.
- **원본에서 해결**: 원래 버전의 상태다. 현재 버전에서 검수 완료한 상태와 같지 않다.
- **같은 시간**: 같은 장면을 보장하지 않는다. 컷 길이·순서·FPS가 달라지면 오차를 다루는 설계가 필요하다.

사용자는 이어받기가 필요하며, 이전 리뷰의 지적 사항이 제대로 반영됐는지 확인하는 경우가 많다고 답했다. 따라서 참조와 이번 버전의 검수를 모두 목업 범위에 포함한다. 질문 도구가 표시되지 않아 후속 질문은 채팅 본문으로 진행한다.

## 이번 버전의 확인 목록

- 기본 상태는 `확인 전`이다. 이어받는 행위만으로 완료 처리하지 않는다.
- `반영 확인`은 현재 영상에서 지적 사항이 잘 수정되었음을 검수자가 확인했다는 뜻이다.
- `추가 수정`은 검수했지만 아직 수정이 더 필요하다는 뜻이다. 원본의 미해결 여부와 독립적이다.
- 확인 목록은 원본 상태 필터와 별개로 유지한다. 원본에서 해결됐다는 이유로 이번 버전의 미확인 항목이 사라지면 안 된다.
- 진행 표시는 `반영 확인 1/3 · 추가 수정 1`처럼 보여 준다. 클릭 가능한 상태 선택으로 잘못 표시한 결과를 되돌릴 수 있다.
- 목업에서 확인 상태는 메모리에만 존재한다. 새로고침하면 초기화되며 `.bframe` 또는 협업 서버에 저장하지 않는다.
- 실제 구현에서는 대상 영상, 원본 파일, 원본 댓글 ID를 함께 써서 중복을 막아야 한다. 기존 댓글을 출처 없이 복사하는 가져오기 기능만으로 이 요구 사항이 충족되지는 않는다. 저장 형식은 구현 설계 단계에서 결정한다.

## 다음 단계에서 검토할 아이디어

- 실제 검수 상태의 저장 위치, 확인한 사람과 시간, 다음 버전으로 다시 이어받는 규칙을 정한다.
- 같은 시간 이동으로 확인하기 어려운 경우 `원본 버전에서 확인`을 제공한다. 누르기 전 영상이 전환됨을 알려야 한다.
- 여러 버전의 반복 지적을 사용자가 묶기. 처음부터 문장 유사도로 자동 병합하지 않는다.
- 두 모니터 사용이 많다면 앱 내부 팝업을 운영체제의 별도 창으로 확장한다.
- 이전 버전 드로잉은 글과 독립된 데이터이므로 별도 범위로 검토한다. 기본값으로 현재 영상 위에 덧그리지 않는다.

## 실제 구현 시 기술 경계

- 읽기는 `electronAPI.loadReview(getBframePath(version.path))` 및 기존 정규화 경로를 재사용할 수 있다. 참조만 읽으면서 `setVideoFile()`로 현재 저장 문맥을 바꾸면 안 된다.
- 여러 버전을 식별할 때 버전 숫자만 쓰지 않고 실제 파일 경로를 포함한다. 같은 v2 이름이나 확장자가 다른 파일도 구분해야 한다.
- 삭제된 댓글 제외, 파일 접근 실패, 리뷰 없음, 빠른 선택 전환 시 오래된 응답 무시, 수동 새로고침 상태가 필요하다.
- 답글·이미지 첨부는 읽기 범위를 유지한다. `drawingsV3`나 레거시 드로잉에 임의 필드를 추가하지 않는다.
- 네이티브 mpv 영상 위에 팝업을 띄우는 경우 오버레이 정책과 키보드 포커스를 실제 Electron에서 확인해야 한다. 브라우저 목업으로 이 문제를 검증할 수 없다.

## 산출물 및 검증

- 대화형 목업: 이 작업의 전용 시각화 폴더 `previous-reviews.html`.
- 리뷰 기능의 기존 코드 변경, 저장 형식 변경, PR 생성, 앱 빌드·배포는 이번 범위에 포함하지 않는다. 사용자 요청으로 추가한 팀원 목록 1행은 예외다.
- 실제 앱에서 영상과 리뷰 파일을 불러오는 검증은 수행하지 않는다.
- 독립 UX 문서 리뷰: 핵심 모순 없음. 시간 이동 대상과 원본 해결 상태의 표현을 구체화하는 두 제안을 반영했다.
- Chrome 152 브라우저 목업 검증: 12개 상호작용 시나리오 pass, fail 0, cancelled 0, 종료 코드 0. 다중 선택, 3개 보기 방식, 정렬, 미해결 필터, 시간 이동, 길이 초과 이동 차단, 답글, 팝업 드래그, Escape 복귀, 빈 상태를 확인했다.
- 화면 폭 약 1024/736/360px에서 3개 모드 총 9개 배치를 검사했다. 가로 넘침 0, 브라우저 실행 오류 0. 기본 화면과 팝업 화면을 스크린샷으로 확인했다.
- 검증 도중 팝업을 드래그하면 포커스가 버튼 밖으로 나가 Escape가 작동하지 않는 문제를 발견했다. 목업의 Escape 수신 범위를 문서로 바꾸고 같은 시나리오를 재검증했다. 앱 코드 수정은 없다.
- 검증 스크립트의 소수점 완전 일치 판정은 range 입력의 반올림으로 실패하여 허용 오차 0.000001초를 적용했다. 프레임 표시와 실제 이동 값은 맞았으며 앱 동작 오류와 구분한다.
- 검증 증거: 목업과 같은 폴더의 `visual-check.json`, `interaction-check.json`, `mockup-1056.png`, `mockup-popup.png`.

### 이어받기 목업 개정 후 검증

- Codex 브라우저에서 직접 20개 검증 항목 성공, 실패 0, 취소 0. UI 도구 실행이므로 프로세스 종료 코드는 해당 없음. 브라우저 오류 로그도 0건이다.
- 기본 빈 목록, 원본 미해결 일괄 추가, 기본 확인 전 상태, 중복 방지, 반영 확인 수 갱신, 원본 상태 유지, 추가 수정 전환, 원본 해결 리뷰의 개별 재검수, 원본 필터 독립, 참고 버전 해제 후 유지, 보기 모드 전환 후 유지, 다중 버전 추가, 기존 검수 결과 유지, 범위 밖 시간 이동 차단, 이어받기 취소의 원본 보존, 취소 후 재추가, 확인 목록의 시간 이동을 확인했다.
- 긴 목록에서 오른쪽 패널 높이 840px, 전체 목업 높이 약 922px를 확인했다. 영상 크기를 유지하고 리뷰 패널에서 스크롤한다. 좁은 화면에서는 패널 높이 제한을 해제한다.
- 데스크톱과 약 343px 콘텐츠 폭의 분리·합쳐·팝업 보기에서 가로 넘침이 없었다. 임시 브라우저 크기 설정은 검증 후 원래대로 복원했다.
- 개정 화면을 스크린샷으로 확인하고 기존 미리보기 탭을 갱신했다. 샘플에서 반영 확인·추가 수정·확인 전 상태를 비교할 수 있다. 새로고침하면 빈 확인 목록으로 시작한다.
- 검증된 목업은 실제 리뷰 저장이나 Slack 전송을 수행하지 않는다. 실제 Electron 영상 오버레이, 파일 저장, 협업 동기화는 구현 단계에서 별도 검증이 필요하다.

## 같은 대화의 별도 요청: 전혜림 팀원 추가

- `renderer/scripts/modules/team-members.js`의 공통 목록에 `전혜림`, Slack UID `U07NBHXV2UW`, 별명 없는 `aliases: []` 항목을 추가했다.
- 적용 경로는 @멘션 자동완성·하이라이트, Slack 알림 발신자/수신자 UID 조회다. 외부 Slack 초대나 메시지 발송은 수행하지 않았다.
- 멘션 이름 조회·파싱, 새 댓글 수신자, 전혜림 발신 알림, 답글 수신자 중복 제거를 모듈에서 검증했다. 실제 전송 함수를 대체하여 5 pass, 0 fail, 0 cancelled, 종료 코드 0.
- 변경 파일 ESLint는 기존 CRLF 규칙을 제외하고 통과했고 `git diff --check`도 통과했다. 로그인 보호 계정 파일은 별도 구조여서 변경하지 않았다.
- 현재 소스에 반영된 상태다. 배포된 앱 적용과 실제 PC UI 검증은 아직 하지 않았다.

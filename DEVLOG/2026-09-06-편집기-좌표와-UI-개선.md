# 편집기 좌표와 UI 개선

## 요청과 범위

기준: `codex/baeframe-reel-editor`의 `648b0d7`, 2.9.0-beta 개발용 편집기. 사용자 요청으로 앞선 UX 보고서를 원본 그대로 보존하고, 다음 문제를 이번 작업에서 다룬다.

- 선택한 획을 이동하면 화면에서 기대한 위치와 크게 다른 곳으로 이동함.
- 선택 도구의 설정 영역이 커지면서 화면 배치가 튐.
- 미리보기·타임라인 드래그가 부드럽고 즉시 반응해야 함.
- Premiere식 C 자르기 상태에서 클릭 위치 분할, V 선택, H 화면 이동.
- 드로잉 키프레임을 확대하고 시간 의미가 있는 눈금 제공.
- 활성 도구의 명확한 표시와 영상 편집·드로잉 작업에 맞는 패널 구성.

기존 V3 문서 구조·리뷰 데이터·원본 영상을 보존한다. 정식 버전 변경, PR, 머지, 배포는 이번 범위에 없다. 이전 UX 보고서의 나머지 심층 점검은 보존된 후속 목록으로 남긴다.

## 구현 방향

- 기존 편집창을 개선한다. 고정 도구 막대·중앙 미리보기·오른쪽 속성·아래 확대 가능한 타임라인을 사용한다.
- 도구 설정은 고정된 높이의 행에 배치하고 추가 설정만 화면 경계를 지키는 팝업으로 연다. 활성 도구에는 선택 강조와 이름, 단축키를 함께 제공한다.
- 출력 프레임을 기준으로 px/frame과 스크롤 위치를 계산한다. 확대해도 포인터 아래 시간 위치가 유지되며, 눈금은 화면 밀도에 따라 초·프레임 간격으로 바뀐다.
- 클립 이동·컷 위치·재생 위치를 포인터 이동 중 표시한다. 파일 저장과 그림 스냅샷은 필요한 시점에만 처리한다.
- 획 이동 문제는 실제 포인터로 재현하고 표시 좌표→Fabric 변형→저장→재표시 경계를 추적해 원인 지점에서 수정한다.

## 작업 분담과 검증

- 드로잉 좌표: 실제 이동 전후 화면 픽셀, 저장된 좌표, 실행취소, 재열기와 출력 PNG를 비교한다. 화면 크기·배율·팬/줌을 포함한다.
- 편집 조작: C 클릭 분할, V/H/B 등 상태, 입력칸 단축키 격리, 시간 눈금·줌 앵커·컷 드래그·스크럽을 행동 테스트와 실제 Chrome/Electron으로 검사한다.
- UI: 선택 패널 전후 영상/타임라인 위치가 같고, 가로/세로 영상과 작은 창에서 도구·속성이 가려지지 않는지 확인한다.
- 원본 런타임을 수정하면 기존 오버레이와 새 편집기 번들을 모두 재생성한다. 관련 테스트와 개발용 빌드·패키지 일치를 확인한다.

## 반영 내용과 원인

- **보고서 보존**: 원본 57개 파일, 2,427,014바이트를 `07db1fb`에 저장했다. `.gitattributes`로 원본 증거의 줄바꿈을 보존하고, Git에 들어가는 바이트를 SHA-256으로 대조해 불일치 0개를 확인했다. [`docs/reports/README.md`](../docs/reports/README.md)에 모바일 주소, 검증 범위와 후속 점검 목록을 남겼다.
- **다중 획 이동 오류**: 실제 Chrome에서 두 획을 함께 옮기면 화면상의 좌표는 맞지만 저장 좌표가 임시 선택 그룹의 내부 좌표 `(0, -90)`, `(0, 90)`으로 바뀌었다. `pointerup` 캡처에서 예약한 microtask가 Fabric의 `object:modified`보다 먼저 이동 기준점을 지우는 것이 원인이었다. `mpv-fabric-overlay-runtime.js`에서 진행 중인 Fabric 변형이 있으면 정리를 이벤트 처리 뒤로 미뤘다. `drawingsV3` 구조는 바꾸지 않았다.
- **확대와 팬 좌표**: `drawing.js`의 `refreshViewport()`가 실제 미리보기 위치와 크기를 동기 반영한다. 확대된 그림의 입력·표시 영역은 미리보기 경계로 제한한다. 실제 Chrome·DPR 1.25에서 화면 이동 40×20px가 원본 좌표 120×60px로 일치하고, 실행취소·다시실행·재열기·PNG에서도 유지됐다.
- **고정 작업 화면**: `editor.html`, `editor.css`, `editor-drawing.css`를 왼쪽 도구 막대, 가운데 영상, 오른쪽 속성, 아래 타임라인으로 정리했다. 선택 설정은 40px 높이의 도구 행에 들어간다. 활성 도구에 강조·이름·단축키·ARIA 상태를 제공한다. 선택 모양 설정과 브러시 팝업도 작업 화면을 밀지 않는다.
- **영상 편집 조작**: `editor.js`와 `timeline-interaction.js`에서 V 선택, C 클릭 위치 분할, H/가운데 버튼 이동을 연결했다. 컷 드래그 중 삽입 위치와 이동 미리보기를 보여준다. 타임라인은 실제 프레임 간격으로 확대하고, 포인터 중심 Ctrl+휠·범위 표시 이동·초/프레임 눈금을 제공한다. 레이어별 그림 유지 구간과 빈 키프레임을 구분한다.
- **탐색 표시**: 빠른 드래그의 마지막 요청 위치를 우선 처리한다. 디코더가 준비되는 동안 직전 합성 화면을 유지한 뒤 영상과 그림을 함께 표시한다. 원본 전환의 디코더 대기 시간을 없앴다고 주장하지 않는다.
- **최종 검토의 추가 수정**: 미리보기 맞춤 계산에서 실제 CSS 안쪽 여백을 제외해 100% 확대 시 1920×1080 비율을 유지했다. 선택된 컷을 드래그할 때 불필요한 재선택을 생략해 컷 내부의 재생 위치도 유지했다. 두 문제 모두 실제 Chrome에서 수정 전 실패와 수정 후 통과를 확인했다.
- **큰 그림 문서의 이동 성능**: 팬·확대·탐색마다 `updateLayerView()`가 V3 전체를 복사하던 경로를 수정했다. 객체 목록은 store revision, 표시·잠금·순서는 레이어 상태 객체가 바뀔 때만 다시 계산한다. 실행취소·다시실행·새 획·레이어 전환·숨김·재열기에서 갱신되는 것을 회귀 검사와 독립 코드 검토로 확인했다.
- **작은 표시 마감**: 키프레임 버튼과 유지 길이 텍스트가 겹치지 않도록 텍스트가 있는 유지 구간만 여백을 둔다. 숨겨진 이전 탐색 입력은 탭 순서에서 제외하고, 범위 이동 컨트롤의 키보드 포커스는 안쪽에 표시한다.

### 최종 패키지 실제 앱 검증

`.cache/editor-electron/polished-run-1788637853727/report.json`: 10단계 통과, 하니스 exit 0, 실제 앱 process exit 0. 별도 APPDATA·LOCALAPPDATA·userData에서 실행하고 파일 연결 등록을 비활성화했다. 파일 선택·저장 경로와 확인창 응답은 fixture이며 나머지는 패키지의 실제 창·입력·IPC·FFmpeg로 검증했다.

- 실제 리뷰 창의 버튼으로 편집창을 열고 영상을 가져왔다.
- 두 획을 실제 포인터로 그리고 함께 38×19px 옮겼다. 두 획의 저장 좌표 이동량이 예상값과 0.0001px 이내로 맞았으며, 저장·재열기한 좌표는 정확히 일치했다.
- C로 24F 위치를 클릭해 24F/48F 컷으로 분할하고 V로 복귀했다.
- 100% 확대 화면이 약 1920×1080을 유지하고 H 드래그가 60×30px를 그대로 따라온 뒤 화면 맞춤으로 돌아왔다.
- 키프레임 버튼과 `48F 유지` 텍스트 사이 5.67px 간격을 확인해 숫자가 가려지지 않았다.
- 이동한 획이 들어간 1920×1080, 72프레임, 3초 H.264/AAC MP4를 실제 출력했다. 첫 프레임을 PNG로 추출해 두 획의 합성을 확인했고 원본 영상 해시는 변하지 않았다.
- 창 닫기를 취소하면 두 창과 저장하지 않은 편집이 유지됐고, 다시 닫을 때 리뷰 창의 실제 저장 응답 후 정상 종료했다. 종료 시간 제한에 의한 강제 종료는 없었다.
- 페이지 오류·편집창 콘솔 오류 0개, 검사 후 해당 실행 파일·격리 프로필 프로세스 0개였다.

최종 화면은 같은 폴더의 `packaged-export-complete.png`, 출력 첫 프레임은 `export-first-frame.png`다. 자동 테스트 1,110개, 실제 Chrome 레이아웃 검사 172개와 위 실제 패키지 검증은 서로 다른 검증 범위로 기록한다.

## 남은 범위

- 이번 변화는 승인된 편집기 작업 화면과 조작의 개선이다. 보존한 UX 보고서 전체의 심층 재감사는 후속 작업이다.
- 대형 프로젝트의 장시간 편집·다양한 실제 촬영 파일·펜 태블릿 하드웨어 전반의 사용성은 이번 합성 영상 검증으로 보장하지 않는다.
- 정식 배포 버전 변경·PR·머지·공유 드라이브 배포는 수행하지 않는다.

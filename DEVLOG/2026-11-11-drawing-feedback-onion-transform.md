# 드로잉 피드백 4건 — 패널 닫힘 단축키, B 키, 어니언 스킨, 변형 상자

브랜치 `claude/drawing-feedback-onion-transform`(기준 `7fedc76`, v2.13.3-beta). 2.14.0-beta 로 올린다(새 기능 둘). PR 은 #235 다. 리뷰·머지·빌드·배포 근거는 원본 체크아웃의 `output/releases/2026-11-11-v2.14.0-beta/` 에 남긴다(머지 뒤에 생기는 값이라 이 문서에 다시 커밋하지 않는다).

## 요청

2026-11-11 에 받은 현장 피드백 네 가지다.

1. 어니언 스킨이 사라졌다. 단축키 `1` 도 안 먹고 버튼도 안 보인다.
2. 단축키 `2`·`3`(빈 키프레임 추가·프레임 추가 등)이 `B` 브러시 패널을 열어 둔 상태에서만 동작한다. 패널이 닫혀 있어도 동작해야 한다.
3. `B` 패널에서 다른 도구를 고른 뒤 `B` 를 누르면 패널이 꺼진다. 패널이 켜져 있고 **브러시를 쓰는 중에** `B` 를 다시 누를 때만 꺼져야 한다.
4. `V` 선택 도구로 고르면 이동만 되고 회전이 안 된다. 애니메이트처럼 변형 상자로 다양하게 다루고 싶다(첨부: 손잡이 여덟 개와 중심점이 있는 자유 변형 상자).

## 확인한 것(원인)

- (1) 구형 팔레트를 걷어낸 PR(#229, v2.12.7-beta)에서 어니언 스킨도 함께 빠졌다. 현재 드로잉 엔진에는 구현이 없었고, 방화벽이 `onionSkinToggle` 을 차단만 했다. 현재 기능표도 "파일럿 미구현" 으로 적혀 있었다.
- (2) 컨트롤러의 `routeKeydown` 이 프레임 조작을 `state !== 'active'` 면 거절했다. 오버레이 쪽도 세션 id 가 있어야만 조작을 받았다.
- (3) `B` 가 조건 없이 `toggle()` 을 불렀다. 구형 도구에서는 "다른 도구면 브러시로, 브러시면 끔" 이었다(커밋 `9ad562e` 의 구형 코드로 확인).
- (4) "Phase 0" 정책으로 이동 외의 변형을 잠가 두었다. 손잡이를 끄고(`hasControls: false`) 크기·회전을 잠갔으며, 전이에 크기·회전이 섞이면 `unsupported-transform` 으로 표시해 저장을 막았다. 반면 저장 형식(`transform` 의 9개 필드)과 검증기 셋, 모든 그리기 경로(`path.set(record.transform)`), 올가미·지우개의 기하 코드는 처음부터 일반 변형을 다룰 수 있게 돼 있었다.

## 구현

### 1. 패널이 닫혀 있어도 프레임 단축키 (`f601fe6`)

- 요청은 세션 id 대신 **영상 정체**로 맞춘다. 컨트롤러가 `sessionId: null` + `stableVideoIdentity` 를 보내고, 호스트(`_drawingActionTokensMatch`·`_normalizePassiveDrawingActionPayload`)가 호스트 세대·영상 세대·입력 리비전·입력 꺼짐·현재 영상 정체를 대조한다. 받는 동작은 프레임 조작 7종과 실행취소·다시 실행뿐이다(`HOST_PASSIVE_DRAWING_ACTIONS`, 컨트롤러 `PASSIVE_DRAWING_ACTIONS`, 파리티 테스트로 묶었다).
- 런타임 `applyPassiveDrawingAction` 이 스토어의 `applyFrameOperation` 을 영상 정체로 부르고, 보기 화면을 다시 그린다. 세션이 없을 때 쓸 소스 크기는 최근 수화·표시에서 기억해 둔 값이다(`rememberVideoDimensions`).
- **실행취소는 그 조작만.** 조작마다 표식(`historyToken`)을 돌려받아 컨트롤러가 `{token, revision}` 으로 기억한다. 패널이 닫힌 상태의 Ctrl+Z 는 맨 위 표식의 리비전이 지금 전역 히스토리 리비전과 같을 때만 오버레이로 가고, 스토어(`applyPassiveStructuralHistory`)는 구조 히스토리의 맨 위가 그 표식일 때만 되돌린다. 아니면 종전의 전역 히스토리 경로로 넘어간다. 표식은 패널을 열거나 영상을 다시 수화하면 버린다.

### 2. B 키 (`f601fe6`)

- `handleDrawModeShortcut()`(app.js): 패널이 열려 있으면 컨트롤러의 `selectBrushFromShortcut()` 을 먼저 부른다. 결과가 `selected` 면 끝, `already-brush` 면 닫는다. `stale`(응답이 늦게 와 상태가 바뀜)이면 아무것도 하지 않는다.
- "지금 도구" 는 오버레이가 `updateDrawingTool` 응답에 실어 주는 `previousTool` 로 판정한다. 렌더러의 사본은 팔레트를 눌러 바꾼 도구를 모른다.

### 3. 어니언 스킨 (`9bf528d`)

- Fabric 캔버스 **아래**에 캔버스를 하나 더 두고(`.mpv-fabric-onion-canvas`) 이웃 키프레임을 한 장씩 스크래치 캔버스에 그려 `globalAlpha` 로 얹는다. 씬·선택·저장과 분리돼 있어 `drawingsV3` 는 바뀌지 않는다.
- 이웃은 **키프레임 한 장** 단위다(홀드 프레임을 세지 않는다). 스토어의 `getOnionSkinScenes` 가 가까운 순으로 돌려주고 빈 키프레임은 건너뛴다. 앞은 파랑(`#6495ed`), 뒤는 초록(`#32cd32`).
- 다시 그릴지 판정은 두 단계다. 값이 싼 열쇠(프레임·설정·내용 리비전·레이어 뷰 리비전·크기)가 같으면 아무것도 하지 않고, 달라졌을 때만 이웃 목록을 뽑아 실제로 그린 내용의 열쇠와 견준다. `after:render` 와 주요 진입점에서 부른다.
- 재생 중에는 숨긴다(app.js 의 `syncFabricOnionSkinPlayback` 이 play/pause/ended/버퍼링과 상태 전이에서 알린다). 숨긴 레이어의 획은 그리지 않는다.
- 단축키 `1` 은 컨트롤러 `routeKeydown` 이 active·passive 모두에서 받는다. IPC `mpv:update-overlay-onion-skin` → 호스트 `updateDrawingOnionSkin`(호스트 세대만 대조, `toggle`·`playing` 두 형태만 받는다) → 런타임 `updateOnionSkin`. 팔레트에는 켬·장수·진하기 줄이 생겼다(편집창 도크에는 없다).

### 4. 선택 도구의 변형 상자 (`a81d518`)

**방식.** 획의 모양 데이터를 다시 굽지 않고 레코드의 `transform` 필드를 쓴다. 저장 형식·검증기·그리기 경로·기하 코드가 이미 지원하고, id 가 그대로라 레이어 배정이 유지된다.

- 손잡이(`createSelectionTransformControls`): Fabric 기본 손잡이(모서리 넷·변 넷) + 위쪽 회전 손잡이 + **모서리 바깥의 회전 영역** 넷. 회전 영역은 모서리 손잡이를 바깥에서 ㄱ자로 감싸며 그리지 않는다 — 둥근 화살표 커서(`ROTATE_CURSOR`)가 유일한 표시다. 판정 우선순위는 넣은 순서의 역순이라 회전 영역을 먼저 넣어 겹치는 자리는 크기 손잡이가 이긴다.
- 모서리는 가로·세로를 따로 늘이고 Shift 로 비율을 지킨다(애니메이트의 자유 변형과 같다). 회전은 Shift 로 15° 단위. 기울이기·뒤집기는 잠갔다(`lockSkewingX/Y`, `lockScalingFlip`).
- 손잡이 치수는 화면 픽셀 기준이다(`resolveSourcePerCssPixel`). 캔버스 격자는 영상 소스 해상도라, 그대로 두면 4K 영상에서 손잡이가 점처럼 작아진다. 화면 배율이 바뀌면 손잡이 묶음을 다시 만든다.
- 커밋(`commitSelectionTransform`): 오브젝트의 변형을 읽어 `sceneStore.transformSelection({ transforms })` 로 한 번에 저장하고, 씬을 다시 세운 뒤 같은 것을 다시 고른다. 여러 개를 골랐을 때 Fabric 의 묶음은 자식 좌표를 묶음 기준으로 들고 있으므로, 자식의 실제 행렬을 `qrDecompose` 로 다시 풀어 저장한다(`absoluteObjectTransform`).
- 외곽선 짝(`syncTransformedOutlinePairs`): 외곽선은 선택 대상이 아니고 본체와 중심이 다르다. 본체가 출발점에서 변한 만큼(`지금 행렬 × 출발 행렬⁻¹`)을 외곽선의 출발 행렬에 곱한다. 끄는 동안과 커밋 때 같은 식을 쓴다.
- 취소·거절(`rollbackSelectTransform`): 본체와 외곽선의 변형 전체를 출발점으로 되돌리고 변형 상자를 그대로 둔다. 배율이 0.01~100 배를 벗어나면 저장하지 않는다.
- 변형 상자를 주지 않는 경우(`selectionAllowsTransform`): 부분 선택으로 세워 둔 조각(아직 문서에 없는 프록시다), 선택 도구가 아닐 때, 숨기거나 잠근 레이어의 획.
- 전이 이벤트에서 `unsupported-transform` 표시를 없앴다. 호스트와 지속화 스토어는 `unsupportedReason !== null` 인 전이를 거절하므로, 이 표시가 남아 있으면 변형이 저장되지 않는다.
- Drawing V3 그림자 어댑터: 크기·회전 전이를 격리하지 않고 `M(지금)·M(기준)⁻¹` 로 받는다. `fabricTransformMatrix` 는 Fabric 의 `composeMatrix` 와 같은 순서이고 테스트가 실제 Fabric 행렬과 1e-9 로 대조한다. 이동뿐이면 종전의 `[1,0,0,1,dx,dy]` 를 그대로 쓴다(행렬 곱의 오차가 끼지 않는다).

**만들다가 찾은 것.**

- **상자 밖 손잡이를 누르면 선택이 풀렸다.** 올가미 선택 방식에서는 런타임이 "고른 것을 눌렀는가" 를 직접 판정하는데(`pointerTargetsActiveSelection`), 상자의 경계 사각형 안인지만 봤다. 회전 손잡이와 회전 영역은 상자 밖이라 새 올가미가 시작되면서 선택이 풀렸다. 손잡이 판정(`pointerTargetsSelectionHandle`)을 먼저 본다. 처음 쓴 테스트는 조작을 쉬지 않고 이어 보내 앞 제스처가 남아 있었고, 그 탓에 런타임이 다음 누르기를 건너뛰어 이 문제가 가려졌다. 조작 사이에 한 박자 쉬게 고친 뒤에 드러났다. 수정을 되돌리면 "올가미 선택 방식에서도…" 테스트가 실패하는 것을 확인했다.
- **Shift 는 기억해 두지 않기로 했다.** Fabric 은 포인터 이벤트에 실린 키만 본다. 펜·터치는 그 값이 비어 오는 환경이 있어 Alt·Ctrl 은 오버레이 문서의 키 상태를 함께 본다. 처음에는 Shift 도 같은 방식으로 넣었다가 뺐다. 호스트는 메인 창으로 넘기는 키의 누름을 삼키고, Chromium 은 삼킨 누름 뒤의 뗌을 내보내지 않는다. 그래서 `Shift+2`·`Shift+3` 같은 단축키를 쓰고 나면 Shift 뗌이 오버레이 문서에 오지 않아, 기억해 둔 값이 눌린 채로 남고 그 뒤의 펜 변형이 "비율 유지·15° 단위" 로 굳는다(v2.13.2-beta 에서 고친 Ctrl 고착과 같은 문제다). 펜 이벤트에 `shiftKey` 가 실려 오지 않는 환경이라면 펜으로는 Shift 를 쓸 수 없지만, 굳는 쪽보다 낫다. 실물 태블릿에서 확인한 뒤에 필요하면 호스트 쪽(Shift 조합의 뗌 보존)과 함께 다룬다.
- **편집창의 화면 비율 변환.** 편집창은 출력 크기가 그림과 다르면 자리와 크기 필드에 비율을 곱했다. 돌리지 않은 획에는 정확하지만, 돌린 획을 가로·세로 다른 비율로 늘이면 틀어진다(45° 돌린 정사각형이 세로로 긴 마름모가 아니라 누운 직사각형이 된다). 그 경우만 행렬로 곱한 뒤 다시 푼다(`rescaleRecordTransform`). 같은 비율이거나 돌리지 않았으면 종전 계산 그대로다.

## 저장 형식

`drawingsV3` 레코드의 키 집합과 `.bframe` 은 바뀌지 않았다. 달라진 것은 `transform` 의 `scaleX`·`scaleY`·`angle`(여러 개를 함께 변형한 경우 `skewX`)에 1·0 이 아닌 값이 들어갈 수 있다는 점뿐이다. 이 값들은 원래부터 형식에 있었고 검증기 셋이 모두 받는다. 이전 버전의 앱도 그리기 경로가 같아 변형한 획을 같은 모양으로 그린다(변형 상자만 없다). 어니언 스킨과 패널 닫힘 단축키는 저장 형식과 무관하다.

변형 상자는 실제 Fabric(jsdom + node-canvas)을 띄워 손잡이 위치에서 누르고·끌고·떼는 방식으로 확인했다: 모서리·변·회전, Shift 비율·15°, 뗌을 놓친 Shift 가 펜 변형에 남지 않는 것, 여러 획(끄는 동안의 화면 행렬과 저장값 대조), 외곽선 짝, 취소·거절 시 복원, 여러 획을 고른 채 취소·제자리 놓기·패널 닫기, 손잡이 크기의 화면 배율 추종, 올가미 방식에서 상자 밖 손잡이, 회전 커서, 누르기를 호스트가 확정한 뒤 되살려 보내는 경로(실제 앱의 입력 경로), 저장 → 보기 화면 → 재수화 → 지우개로 자른 뒤 **픽셀 대조**(남은 조각이 제자리에 있는가), 편집창의 저장·다시 열기·PNG 내보내기.

실제 앱 조작(2026-11-11, 후보 빌드 `8aa6c1e` 의 `dist/win-unpacked/BFRAME_alpha_v2.exe`, 격리 프로필, 640×360 24fps 시험 영상). Playwright 로 패키지된 앱을 띄우고 메인 창에는 키 입력을, 오버레이 창에는 마우스 입력을 DevTools 프로토콜로 넣었다. 전 항목 통과, 페이지 오류 0건.

| 항목 | 확인한 것 |
|---|---|
| 패널을 닫은 채 `2` | 오버레이의 씬이 0 → 1, 타임라인 표시 0 → 1. 그리기 패널은 열리지 않음 |
| 패널을 닫은 채 Ctrl+Z · Ctrl+Y | 씬 1 → 0 → 1 → 0, 타임라인 표시도 함께 돌아옴. `3` 후 Ctrl+Z 도 원래대로 |
| `B` | 선택 도구에서 `B` → 브러시로 바뀌고 패널 유지. 브러시에서 `B` → 패널 닫힘 |
| 변형 상자 | 획을 고르면 손잡이가 뜸(화면 갈무리로 확인). 모서리에서 크기 커서, 모서리 바깥에서 회전 커서. 모서리를 끌어 크기, 모서리 바깥을 끌어 회전. 각각 실행취소 한 단계 |
| 저장 | `.bframe` 의 그 획에 `scaleX 1.229 · scaleY 1.264 · angle 29.27°` 가 저장됨. Ctrl+Z 두 번·Ctrl+Y 두 번으로 오감 |
| 어니언 스킨 | 패널을 닫은 채 `1` → 토스트 "어니언 스킨 켜짐", 아래 캔버스에 앞 그림이 파랑(평균 RGB 100·149·238)으로 깔림. 재생하면 숨고 멈추면 다시 보임. `1` → 꺼짐. 팔레트에 어니언 스킨 줄이 있음 |

처음 돌렸을 때는 첫 항목에서 멈췄다. 앱이 아니라 점검 스크립트의 잘못이었다 — `data:` 주소의 창이 둘(mpv 를 담는 창과 그리기 오버레이)인데 앞의 것을 골랐고, 타임라인 표시의 클래스 이름을 틀리게 적었다.

미확인:

- 실물 마우스·키보드로 사람이 직접 조작하는 확인(위 조작은 자동 입력이다). 실제 제작 영상(고해상도)에서의 손잡이 크기 체감.
- 실물 펜 태블릿: 손잡이를 펜으로 잡는 감각, 펜으로 Shift 를 누른 채 끌기.
- 다른 PC 와의 동시 편집 중 변형.

## 독립 리뷰와 반영

다른 담당(코드 리뷰 에이전트 둘)이 커밋을 읽기 전용으로 검토했다. 하나는 패널 닫힘 단축키·B 키·어니언 스킨(`f601fe6`·`9bf528d`), 하나는 변형 상자(`a81d518`)를 맡았다. 보안·IPC 경계(패널 닫힘 요청과 어니언 스킨 요청을 허용 목록으로 다시 짜는 것, `JSON.stringify` 로 끼우는 것, 실행 시점의 영상 정체 재확인), 되돌리기 범위, 저장·타임라인 재동기, 어니언 스킨의 캐시 열쇠·재진입·내보내기 격리, 행렬 계산, 편집창 비율 변환, 외곽선 짝, 누르기 확정·재생 경로에서는 결함을 찾지 못했다. 아래는 지적받아 고친 것이다.

| 지적 | 반영 |
|---|---|
| (major) 재생을 멈춘 뒤에도 어니언 스킨이 계속 숨겨질 수 있다. 정지 알림을 보내지 못하면 기억을 "새 오버레이·정지" 로 되돌렸는데, 그러면 다음 정지 알림이 "기본값 그대로" 로 걸러진다 | 못 보낸 경우 "모름" 으로 적어 다음 호출이 무조건 다시 보낸다 |
| (major) 여러 획을 고른 채 크기·회전을 취소하면 보이지 않는 실행취소 단계와 저장이 생긴다. 되돌린 뒤 변형을 끝내면 Fabric 이 `object:modified` 를 내고, 묶음에서 다시 푼 값(각도 310° ↔ -50°, 1e-16 반올림)이 저장값과 `!==` 라 커밋됐다 | ① 취소가 낸 `object:modified` 는 받지 않는다 ② 화면의 행렬이 저장된 변형과 같으면 저장된 값을 그대로 넘긴다 ③ 묶음에서 푼 각도를 [0, 360) 으로 맞춘다. 끌었다가 제자리에 놓는 경우와 끄는 도중 패널을 닫는 경우도 같은 보호를 받는다 |
| (minor) `2` 를 누르고 곧바로 Ctrl+Z 를 누르면 프레임 조작 대신 전역 히스토리(댓글 등)가 되돌려진다. 표식은 응답이 와야 알 수 있는데 판정을 키를 누른 자리에서 했다 | 응답을 기다리는 조작이 있으면 키를 받아 두고 큐의 제 차례에 판정한다. 그때 닫은 채 한 조작이 맨 위가 아니면 전역 실행취소로 넘기고, 표식을 버린다(남기면 뒤이은 Ctrl+Y 의 순서가 뒤집힌다) |
| (minor) 오버레이가 패널 닫힘 실행취소를 거절하면 키가 그냥 사라진다 | 오버레이가 "그 조작은 맨 위가 아니다"(`history-mismatch`·`history-empty`)라고 답했을 때는 전역 실행취소로 넘긴다. 전송 실패는 넘기지 않는다(오버레이가 실제로는 되돌렸을 수 있어 두 번 되돌리게 된다) |
| (minor) "지나치게 작게" 테스트가 커밋이 거절돼도 통과한다 | 실제로 줄었는지와 실행취소 단계가 하나 늘었는지를 함께 본다 |
| (low) 변형을 저장하며 씬을 다시 세울 때 `object:modified` 가 한 번 더 난다(지금은 해가 없다) | 저장한 뒤의 알림은 받지 않게 막았다 |

재현 테스트는 수정을 되돌리면 실패하는 것을 확인했다(변형 취소는 세 보호를 모두 끄면, 그리고 각도 맞춤만 남겨도 실패한다).

고치지 않고 둔 것:

- 어니언 스킨 토글의 응답이 8초 기한을 넘기면 렌더러는 실패로 보고 토스트를 띄우지 않지만 오버레이는 토글을 적용한다. 다시 누르면 꺼진다. 기한을 넘길 만큼 느린 경우가 드물고 결과가 가벼워 그대로 두었다.
- 패널이 닫힌 상태의 프레임 단축키는 재생 중에도 받는다(그 순간의 프레임에 적용된다). 패널이 열려 있을 때와 같다.

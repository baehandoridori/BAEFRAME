## 조사 방식

리뷰창은 기존 패키지 EXE와 전용 프로필·합성 영상/댓글로 실제 조작하고 네이티브 영상·Fabric을 포함한 앱 영역을 캡처했다. 외부 HTTP(S) 차단으로 Pretendard 일부 CDN 요청도 차단되어 글꼴 폭 측정은 오프라인 조건으로 한정했다. 편집창은 현재 renderer와 실제 드로잉·마우스/키보드·영상 디코딩을 사용하고 파일 IPC는 fixture로 연결했다. 출력43%는 표시 검토용 주입이다. OS 배율·펜·실제 수신자 협업·출력 품질은 별도 검증으로 남겼다.

## 주요 발견과 권고

새로 연 그림 프로젝트의 V 활성 표시/실제 입력 불일치, 열기 실패 후 미리보기 준비 표시 잔류, 이름 입력 중 Ctrl+S 무동작을 재현했다. 긴 헤더와 좁은 창의 핵심 조작 밀림, 큰 리뷰 팔레트, 시간 단위·선택 컷 정체성·겹친 키·저장 위치의 지속성 등을 실제 화면·코드와 대조했다. 이미 정상화된 획 좌표, 편집 도구 전환 배치, 팬 중 V3 불변은 보존 항목으로 구분했다.

핵심 권고는 두 작업 문맥을 유지하며 문서·도구·선택·시간·저장 문법을 공유하는 것이다. 영상 정지와 그림 유지, 전체 편집과 컷 로컬 시간을 구별한다. 색·글자 축소보다 패널 경계 조절과 선택 컷 상세를 우선한다. 구조도는 미구현이며 파일 형식 통합이나 모든 제안 기능의 구현 승인을 뜻하지 않는다.

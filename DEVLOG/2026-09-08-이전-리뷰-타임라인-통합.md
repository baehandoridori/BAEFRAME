# 이전 리뷰 옵션과 타임라인 실제 앱 통합

작성일: 2026-09-08

## 요청과 원인

사용자가 옵션·타임라인 목업을 승인하고 실제 앱 적용을 요청했다. 직전 앱에는 `createPreviousReviewPanel`에서 댓글 목록으로 전달하는 경로만 있었으며, 타임라인의 `renderCommentRanges()`에는 현재 댓글만 들어갔다. 목업에 존재하던 이전 버전 행이 실제 앱에는 연결되지 않은 상태였다.

## 구현

- 댓글 패널은 높이 40px의 토글/선택 버전/옵션 한 줄로 정리한다. 버전 선택, 다시 읽기, 일괄 이어받기, 분리/합쳐/팝업 보기, 타임라인 표시 옵션은 고정 위치의 작은 팝업에 둔다.
- 이전 리뷰를 처음 켜면 리뷰가 저장된 가장 최근 버전을 선택한다. 명시적인 이어받기 전에는 원문 참조이며 저장 항목을 생성하지 않는다.
- `previous-review-timeline.js`는 현재 댓글 트랙 바로 다음에 출처 경로별 행과 대응하는 왼쪽 헤더를 생성한다. 현재 댓글 트랙 내부에 넣지 않아 현재 댓글 갱신/숨김이 이전 리뷰를 지우지 않는다.
- 버전 이름과 색을 함께 표시한다. 해결 항목은 빈 표식과 체크, 미해결은 채운 표식이다. 같은 버전의 표식이 40px보다 가까우면 별도 높이에 배치한다. 줌/너비 변화에 다시 배치하고 헤더 높이도 일치시킨다.
- 타임라인 클릭은 기존 패널의 FPS 변환과 시간 범위 검사를 거쳐 현재 영상으로 이동한다. 카드와 표식을 함께 강조한다. 범위 밖/시간 없음 항목은 헤더에 개수만 표시하고 임의의 시점으로 이동시키지 않는다.
- `onTimelineChange`를 통해 토글, 선택 버전, 해결 상태, 상태/작성자/검색 필터 변경을 전달한다. 영상 전환과 합산 타임라인 문맥에서는 이전 행을 제거한다.
- 팝업 보기는 기존 댓글 창의 DOM 이동/복원 컨트롤러를 재사용한다. `baeframe-previous-reviews` 이름과 기존 `comment-panel.html` 문서의 조합만 추가 허용하며, 자식 창에는 파일 IPC/Node 권한을 부여하지 않는다. 부모와 동일한 매니저를 사용해 상태가 즉시 동기화된다. 현재 댓글 분리 창과 독립된 이름/화면 상태를 사용한다.
- 원본 미해결/해결 계승은 기존 `ReviewCarryoverManager` 로직을 유지한다. 원본 파일은 바꾸지 않는다.

## 검증 진행

- 최초 누락 재현: 관련 검사 34개 중 28 pass, 6 fail, 0 cancelled. 이전 리뷰의 타임라인 전달, 실제 행 렌더러, 보기 선택, 전용 팝업 허용 누락을 확인했다.
- 현재 자동 회귀: 139 pass, 0 fail, 0 cancelled, exit 0. 패널/타임라인/팝업/상태 계승/저장/버전 전환/루트 포맷/프레임 격자/댓글 클러스터를 포함한다.
- ESLint: Windows 체크아웃의 기존 CRLF 줄바꿈 규칙만 제외하고 `--no-ignore`로 검사. 0 errors, 기존 app.js 미사용 변수 경고 18개, exit 0.
- 실제 Electron: 별도 `options-profile`과 복제한 `options-media`에서 진행한다. 외부 HTTP 요청을 차단하여 테스트 데이터가 외부 협업/알림에 전달되지 않게 했다. 기존 사용자 시연 프로필과 리뷰 파일은 보존한다.
- 실제 화면에서 v3 행, 표식 3개, 범위 밖 1개, 40px 옵션 바가 보임을 확인했다. 세부 조작 검증은 실행 기록에 계속 기록한다.

검증 로그와 스크린샷: `.superpowers/previous-review-demo/options-*`.

## 최종 실제 앱 검증

최종 자동 회귀는 **139 pass, 0 fail, 0 cancelled, exit 0**이다. ESLint는 위 조건에서 **0 errors, 기존 warning 18개, exit 0**, `git diff --check`도 통과했다.

Electron의 실제 화면에서 자동 조작한 결과(`options-timeline-e2e.json`):

- `ready: true`, renderer errors 0.
- 최초 v3 행 1개/표식 3개/범위 밖 1개. 화면 안에 표시됨(`inView: true`).
- 타임라인 표식을 눌러 HTML 영상 **3.001초**, 표시 시간 **00:00:03:00 / 72프레임** 이동.
- 40px 옵션 바, 3가지 보기 방식. 옵션 팝업의 좌표·크기와 `elementFromPoint`로 실제 화면에서 클릭 가능함 확인(`onScreen: true`).
- 일괄 이어받기: 원본 **미해결 3개, 해결 1개** 그대로 유지.
- 합쳐 보기: 현재 댓글 목록에 이어받은 4개 표시.
- 실제 `BAEFRAME 이전 리뷰` 창: 항목 4개, 파일 IPC 미노출. 이 창에서 해결 상태를 바꾸면 메인 타임라인의 해결 표시도 즉시 변경.
- 팝업 복귀, 이전 리뷰 토글 off/on, 타임라인만 숨김/복구, v2 추가를 조작. 최종 **v3/v2 행 2개, 표식 6개**.
- 실제 화면 스크린샷 `options-timeline-popup-options.png`, `options-timeline-app.png` 확인.

시행착오도 구분한다. 첫 네이티브 실행은 샌드박스 GPU 프로세스 오류로 실패했고, 별도 권한으로 격리 앱을 실행했다. 자동 조작은 백그라운드 rAF 제한과 닫힌 창의 `executeJavaScript` 응답 대기 때문에 검증 하네스가 멈춰 이를 보완했다. 제품 코드의 별도 문제로 댓글 패널의 `backdrop-filter`가 고정 팝업의 좌표 기준을 바꿔 화면 밖으로 밀어내는 것을 실제 화면 검사에서 발견했다. 팝업을 소유 문서 body로 옮겨 화면 좌표로 배치하고 닫을 때 복원하도록 수정한 뒤 실제 클릭 가능한 위치를 재검증했다.

자동 검증용 `options-profile/options-media` 앱은 종료했다. 조작용 앱은 기존 `profile/media`와 새 `launch-options-demo.cjs`를 사용해 다시 열었다. 기존 시연 항목을 임의로 이어받거나 상태를 바꾸지 않는다. `시연실행.ps1`도 새 실행 파일을 사용한다.

## 이번 범위 밖

PR 생성, 머지, 배포와 여러 PC에서의 동시 협업 검증은 수행하지 않았다. 네이티브 검증의 재생 엔진은 HTML 영상 경로이며 mpv 재생 경로를 별도로 검증하지 않았다.

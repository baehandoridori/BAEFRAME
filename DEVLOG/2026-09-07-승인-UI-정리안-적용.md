# 승인한 UI 정리안 적용

## 사양과 범위

2026-09-06 시안에 대해 사용자가 2026-09-07 "UI는 이정도면 될 듯", 이어 "ㄱㄱ"로 실제 적용을 승인했다. 기준은 `mockups/2026-09-06-ui-refinement/`의 기본/드로잉/BEditer 정리안이다.

- 기존 배치, 노란 기본 강조색, 재생목록의 선택적 열기/닫기 유지.
- BAEFRAME 헤더·파일명·재생 컨트롤·댓글·타임라인의 간격, 정렬, 대비 정리.
- 네이티브 Fabric 팔레트 크기와 선택 설정 정렬, 실제 활성 도구 표시.
- BEditer 기존 도구 레일·뷰어·속성·타임라인 구조에서 컨트롤 크기와 정렬 정리.
- 저장 형식, 편집 동작, IPC 권한, 단축키 정책 변경 없음. 화면 검증에서 재현한 필터 메뉴의 가로 넘침과 설정 메뉴 닫기 오류는 함께 수정한다.
- 시안의 고정 상태와 하드코딩 색은 그대로 복사하지 않고 런타임 상태와 기존 테마에 연결한다.
- 로컬 적용과 검증까지. PR·머지·공유 드라이브 배포는 이번 요청에 포함하지 않는다.

4. [완료] 관련 자동 검사, 실제 앱 화면 및 키보드/포인터·창 크기·테마 검증. 테마 설정 뒤 페이지 가로 밀림 수정 및 재검증.
5. [완료] 변경 리뷰, 검증 결과 기록. 이 문서와 구현·검증 증거를 같은 로컬 커밋에 보존한다.

## 작업 기준

- 작업 브랜치: `codex/baeframe-ui-refinement`, 기반 `047ade2`.
- 기존 격리 worktree `baeframe-ux-first` 재사용. main과 미추적 보고서·시안은 보존한다.
- 시안 팔레트의 `::after { content: '선택' }`는 고정 문구이므로 실제 활성 도구에 맞춰 표시한다.
- 시안의 고정된 화면 크기에만 맞추지 않고 작은 창/테마/접힌 패널을 검증한다.

## 적용 내용

- `renderer/styles/main.css`: 헤더 48px, 재생부 52px, 버튼 높이와 간격 통일. 실제 파일명을 한 줄로 표시하고 `app.js`에서 전체 경로를 툴팁으로 제공한다. 1250px 이하에서는 일부 헤더 버튼을 기존 아이콘으로 표시하며 제목과 접근성 이름을 유지한다.
- 댓글의 필터·카드·입력부 여백과 테두리를 정리했다. 좁은 댓글 패널에서는 필터가 다음 줄로 넘어간다. 일반 카드의 완료 버튼과 타임코드가 겹치지 않도록 확보한 여백은 컴팩트 댓글과 재생목록 집계 댓글에 적용하지 않는다.
- 타임라인의 기존 격자는 유지하면서 대비를 낮췄다. 패널 배치와 재생목록 열기·닫기 상태는 기존 로직이 결정한다.
- `main/mpv-overlay-host.js`: 기존 네이티브 드로잉 팔레트를 212px 폭으로 정리하고 선택 대상·영역 모양을 각 한 줄에 배치했다. 작은 높이에서는 내용만 스크롤하며 팔레트 이동·접기와 기존 버튼 상태를 유지한다.
- `mpv-fabric-toolbar.js`, `mpv-fabric-overlay-runtime.js`: 실제 활성 도구 이름을 팔레트 제목에 표시한다. 브러시·선택·선 도구 전환을 런타임 검사로 확인했다. 공용 런타임을 사용하는 두 생성 번들도 갱신했다.
- `editor.css`, `editor-drawing.css`: 기존 BEditer의 도구 레일·우측 속성·하단 타임라인을 유지하고 입력란·버튼·재생 컨트롤을 정렬했다. 비활성 버튼, 선택한 홀드, 키보드 포커스 표시는 유지한다.
- 메인 화면은 기존 테마 변수를 사용한다. 네이티브 팔레트는 기존 협업 테마 전달 경로를 이용해 밝고 어두운 테마에 대응하며 기본 노란 강조색을 사용한다. 네이티브 팔레트의 사용자 지정 강조색 전달은 이번에 새로 추가하지 않는다.

## 화면 검증과 리뷰

- BAEFRAME: 격리 프로필과 합성한 6초 로컬 영상, 예시 댓글·획을 사용해 실제 Electron/MPV 앱을 조작했다. 스타일 주입이나 DOM으로 화면 상태를 꾸미지 않았다. 네트워크 요청은 차단하고 파일 선택기만 예시 영상으로 고정했다.
- 실제 패키지에서 재생목록 기본 닫힘/열기/닫기, 파일명 툴팁, 댓글 컴팩트 전환, 도구 선택 표시, 팔레트 접기/펼치기, 1050×720 창의 헤더 버튼, 밝은 테마와 네이티브 팔레트 테마 전달, 설정 후 문서 폭과 메뉴 닫기 등 11개 검사를 통과했다(exit 0). 페이지 오류 0. 컴팩트 검사에서는 전환 직후가 아닌 레이아웃이 반영된 뒤 여백 0px를 확인한다.
- BEditer: 실제 renderer와 생성 번들을 Chrome에서 실행하고 IPC만 예시 프로젝트로 고정했다. 1440×900 및 1050×720에서 3개 컷·2개 드로잉 레이어·선택 홀드·포커스·브러시 팝업·프레임 36→37·드로잉 접기 동작을 확인했다. 페이지 오류와 레이아웃 문제 0. 영상 타임라인의 의도된 가로 스크롤은 오류로 분류하지 않았다.
- 독립 리뷰에서 컴팩트 댓글에 일반 카드 여백이 섞이던 부분을 수정했다. 필터 줄바꿈까지 포함한 최종 스타일·테스트 diff는 승인 사양에 부합하며 추가 이슈가 없다는 판정을 받았다.

- 펜 압력, 외부 사용자의 협업 연결, 공유 드라이브 배포 및 다른 PC의 실행은 이번 검증에 포함하지 않는다.

### 화면 검증에서 추가로 발견한 문제

- 설정을 열고 닫은 뒤 화면이 160px 왼쪽으로 밀리는 현상을 실제 패키지에서 발견했다. 오른쪽 댓글 필터의 숨은 메뉴가 `left: 0`으로 배치되어 문서 폭을 1440px에서 1600px로 늘리는 것이 원인이었다. 메뉴를 래퍼 오른쪽에 정렬해 열리거나 닫힌 상태 모두 화면 안에 두었다.
- 앱 설정 진입 시 기존 메뉴는 실제 열림 클래스 `open` 대신 `show`를 제거하고 있었다. `open`과 설정 버튼의 `active`를 함께 해제하도록 수정했다.
- 수정 전 실제 패키지에서 두 동작을 검사해 실패(exit 1)를 확인했다. 수정 후 재빌드한 패키지에서는 `scrollX=0`, 문서 폭/창 폭 모두 1440px, 이전 메뉴와 버튼의 열림 상태 모두 false로 통과했다. 1050px 메뉴 정렬도 실제 HTML/CSS의 별도 브라우저 검증에서 확인했다.
- 마지막 두 수정 후 `test:ux` 69/0/0, lint 오류 0/경고 65, build exit 0을 다시 확인했다. 관련 없는 영역의 통과 검사는 중복 실행하지 않았다. 두 수정의 독립 리뷰도 추가 이슈 없음.

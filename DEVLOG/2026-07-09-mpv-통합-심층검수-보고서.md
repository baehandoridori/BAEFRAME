## 1. 안정성 평가: 조건부 안정

### 잘 된 것 (검증 통과)

- **loadfile 직렬화**(`loadQueue`), 스테일 로드 토큰, wid 변경 시 재시작 등 정상 경로 설계가 꼼꼼함
- IPC 파이프 이름이 `pid+시간+난수`로 충돌 없음, 다중 인스턴스 안전 (`main/mpv-manager.js:32-45`)
- mpv 로드 **초기 실패** 시 FFmpeg/HTML5 경로로 자동 폴백 + 토스트 통보가 실제로 동작 (`renderer/scripts/app.js:6982-6991`)
- 바이너리 번들링·탐색 경로가 electron-builder.yml과 정확히 일치, asar 문제 없음
- 렌더러→mpv 임의 명령 주입 경로 없음 (모든 IPC가 구체 메서드 매핑, 셸 미경유)
- ~~앱 강제 종료 시 mpv 좀비 잔존~~ → **기각됨**: libuv가 자식 프로세스를 `KILL_ON_JOB_CLOSE` Job Object에 자동 할당하므로 메인 프로세스가 죽으면 mpv도 함께 종료됨

## 2. 호환성 평가

### 포맷: mpv 우위

기존 경로는 코덱 5종(h264/avc1/vp8/vp9/av1) 외 전부(ProRes, DNxHD, HEVC 등)를 **8bit yuv420p H.264로 재인코딩**하며, 이때 10bit 손실과 색공간 강제 변환(`iall=bt601-6-625` — bt709 소스 색 왜곡 위험, `ffmpeg-manager.js:616`)이 발생한다. mpv는 원본 무변환 직재생이므로 **색 검수 관점에서 실질적 품질 향상**이다.

### 리스크

- `--hwdec=auto`는 매뉴얼 권장(`auto-safe`)보다 공격적 — 팀원별 GPU/드라이버 편차 우려 (`mpv-manager.js:83`)
- 번들 mpv가 **버전 고정 없는 git master 개발 빌드**(v0.41.0-744), mpv/README.md 문서와도 불일치
- G: 드라이브(Drive 스트리밍) 대비 기동 4초/로드 3초 타임아웃이 짧음 — 미캐시 파일에서 실패 가능, 실측 미실시
- 알파 채널 소스가 mpv에서 체커보드 배경으로 표시(기존 경로와 표시 상이)
- 내장 자막/다중 오디오 트랙 억제 인자(`--sid/--aid/--sub-visibility`) 없음 — 자막 내장 소스에서 자동 표시 가능
- GPL 바이너리(mpv + BtbN FFmpeg) 동봉 라이선스 고지 파일 전무
- **화면 공유/창 캡처 비호환**: mpv 영상이 별도 네이티브 창이라 '창 단위' 캡처·공유에서 영상 영역이 빈 화면으로 보임 (구조적, 전체 화면 공유로는 보임)
- 절전/화면 잠금 복귀 처리 0건 (`powerMonitor` 미사용) — hwdec 디바이스 로스트 시 복구 없음
- mpv 진단 로그 전무 (`stdio: 'ignore'`, `--log-file` 없음) — 파일럿 평가용 실사용 데이터를 모을 수단이 없음

## 3. FFmpeg 인코딩 시스템 전면 교체: 불가 (유지 필요)

FFmpeg 소비자 지도 (mpv로 대체 불가한 것들):

1. **mpv 실패 시 런타임 폴백** — 유일한 안전망. 설계 스펙(`2026-06-21-mpv-pilot-design.md`)이 "Do not delete or weaken the current FFmpeg path" 명시
2. **스플릿 뷰** — HTML5 video 2개 병렬 구조, 미지원 코덱은 트랜스코드 필수 (`split-view-manager.js:1170-1215`)
3. **합성 레이어 미디어 준비** — 레이어는 mpv 모드에서도 Chromium이 디코딩 (`app.js:5477-5510`)
4. **타임라인/스크럽/댓글 썸네일** — HTML5 video + canvas 캡처 구조
5. **최근 파일 썸네일** — `ffmpegManager.ffmpegPath` 직접 의존 (`recent-thumb-capture.js:40-50`)
6. **재생목록 연속재생 사전변환** — mpv 미사용 사용자/폴백 사용자 전원이 이 경로
7. **ffprobe 코덱 판정** — isSupported 분기·캐시 검증의 기반

mpv가 자연 대체하는 것은 **메인 단일 영상 재생의 트랜스코드 1개**뿐. 제거 실익은 설치 용량 ~331MB 절감이 전부이고, 제거 시 위 6개 기능이 즉사하며 mpv 장애 시 영상 재생 수단이 사라진다.

> 참고: 오디오 파형은 FFmpeg 무관(WAV 직접 파싱 + Web Audio 폴백)이므로 교체 논의에서 제외 가능.

## 4. 권고 로드맵

### P1 — 파일럿 확대 전 필수 (지금)

- [ ] **fps 정합 통일**: HTML5 24 고정 vs mpv container-fps 이원화 해소 + mpv 세션 종료 시 fps 리셋. 한 명이라도 mpv를 켜면 팀 전체 리뷰 데이터 정합성이 깨지므로 최우선
- [ ] **그리기 모드 영상 숨김 해소**: `.drawing-tools.visible` 차단 셀렉터 구조 재설계
- [ ] **크래시/행 복구 체계**: (a) `externalstopped` 시 현재 파일 자동 재로드+토스트, (b) getStatus 연속 실패 워치독 → kill+폴백, (c) main exit 시 렌더러 즉시 통보
- [ ] **렌더러 크래시/리로드 시 mpv 정리**: `render-process-gone`/`did-navigate`에서 `mpvManager.stop()` + 호스트 destroy

### P2 — mpv 기본 승격의 전제

- [ ] mpv 스크린샷 IPC 신설 → 썸네일 파이프라인(필름스트립·스크럽·댓글) 복구
- [ ] IPC를 지속 연결 1개 + 명령 큐 + `observe_property` push 구조로 교체 → 프레임 동기화를 HTML5 수준으로, end-file 이벤트로 크래시 즉시 감지
- [ ] 스플릿 뷰·합성 레이어의 비HTML5 코덱 대안 설계
- [ ] mpv 로그 수집(`--log-file` 또는 stdout 파이프) — 파일럿 평가 데이터 확보

### P3 — 배포 위생·승격 판단

- [ ] mpv 바이너리 안정 릴리스로 버전 고정, `--hwdec=auto-safe` 검토
- [ ] G: 드라이브 실환경 타임아웃·경로 비교 실측, 절전 복귀 시나리오 확인
- [ ] GPL 라이선스 고지 파일 추가
- [ ] `thumbnail:generate-video`의 ffmpeg 탐색 경로가 `mpv/` 폴더를 가리키는 버그 수정 (`ipc-handlers.js:2377-2378`, 현재 사실상 항상 실패 → Canvas 폴백으로만 동작)
- [ ] EOF 후 재생 버튼, stale 폴링 되돌림, 구간반복 끝 근처 루프 등 UX 결함 일괄 수정
- [ ] **파일럿 → 기본 승격 기준 문서화** (현재 어디에도 없음) → 팀 전체 옵트인 2~4주 실사용 후 재평가

### 장기 방향

전면 제거가 아니라 **부분 축소**: 메인 재생 트랜스코드 수요가 소멸하면 캐시 한도 축소 → 썸네일·스플릿 뷰·합성 레이어가 mpv 스크린샷 기반으로 재설계된 후에야 ffmpeg.exe 제거 논의 가능 (ffprobe는 그때도 잔존 가능성 높음).

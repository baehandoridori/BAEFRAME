# 접속하지 못한 사람에게 "다시 연결" 이 보이지 않음 — 재접속 입구를 상단으로

브랜치 `claude/collab-rejoin-indicator`(기준 `298e176` — PR #243 의 v2.16.4-beta 위에 쌓았다. 같은 파일을 고치기 때문이다). 2.16.5-beta 로 올린다.

## 요청

2026-11-18, v2.16.3-beta(PR #242, 해결 표시가 실시간으로 전해지지 않던 문제)를 배포한 뒤 팀 안내문을 쓰다가 "접속하지 못한 사람은 동기화 상태 표시를 눌러 다시 연결할 수 있다" 는 문장을 확인하려고 화면 코드를 다시 읽었고, 누를 수 없다는 것을 알았다. 사용자에게 알리고 고칠지 물었고 2026-11-20 에 "고쳐 줘" 를 받았다.

## 조사

- 직접 다시 연결하는 입구는 동기화 아이콘(`#syncStatus`)의 클릭 처리기 `showCollaborationSyncStatus()` 하나였다.
- `#syncStatus` 는 `index.html` 에서 협업자 표시(`#collaboratorsIndicator`) 안에 있다. 협업자 표시는 처음부터 `style="display: none;"` 이고 `updateCollaboratorsUI()` 가 참여자가 한 명 이상일 때만 보이게 한다. 참여자 목록은 방에 들어간 뒤의 이벤트(`collaborationStarted`·`collaboratorsChanged`)에서만 채워진다.
- 그래서 방에 들어가지 못한 사람에게는 협업자 표시가 통째로 보이지 않고, 그 안의 입구도 보이지 않는다. mpv 재생 중의 미러(오버레이 창의 `#mpvCollaborationBadge`)도 원본이 보일 때만 보인다.
- v2.16.3-beta 에서 실제로 동작한 것: 접속 실패 안내(토스트 한 번), 자동 재접속 최대 6번(1·3·5·10·10·10분), 파일 다시 열기.

### 왜 놓쳤나

- 실제 앱 점검(`app-smoke-collaboration.cjs`)이 `document.getElementById('syncStatus').click()` 으로 눌렀다. 이 호출은 숨겨진 요소에도 클릭을 보낸다. 점검은 "누르면 다시 접속한다" 만 봤고 "사용자가 누를 수 있다" 는 보지 않았다.
- 자동 검사는 `showCollaborationSyncStatus` 의 소스에 재접속 호출이 들어 있는지만 봤다.
- 독립 리뷰 세 건도 로직의 순서를 따라갔고 화면에서의 자리는 보지 않았다.

### 함께 드러난 것

입구가 보이면 그동안 닿지 않던 경로가 실제로 쓰인다. 재접속 기록의 수명을 다시 따졌다.

- 재접속 기록은 로드 토큰으로 "지난 것" 을 가렸다. 그런데 로드 토큰은 파일이 그대로여도 올라간다 — 영상 전환이 취소됐을 때(저장 실패 확인 창에서 취소, 열 수 없는 파일을 고름), 같은 파일의 재생 엔진만 바꿀 때(`engineSwap`). 그러면 다음 차례에 재접속 기록이 조용히 버려져 자동 재접속이 멈췄다. 입구가 보이는 지금은 "눌렀더니 표시만 사라지고 아무 일도 없는" 모양이 된다.
- 다른 파일로 넘어가도 재접속 기록은 다음 타이머가 돌 때까지(자동 시도가 끝난 뒤라면 계속) 남아 있었다. 표시를 기록에 맞춰 그리면 지난 파일의 표시가 새 파일 위에 남는다.
- 직접 누르는 시도에는 간격 제한이 없었다. 거절된 접속도 서비스 사용량으로 잡힐 수 있고(2026-11-18 에 월 한도 거절을 한 번 받았다), 보이는 버튼은 여러 사람이 연달아 누를 수 있다.

### 고른 것과 고르지 않은 것

- **협업자 표시를 보이게 하지 않고 표시를 따로 뒀다.** 협업자 표시에는 인원 수("0명 작업 중"), 마우스를 올리면 뜨는 플렉서스 패널, mpv 미러가 딸려 있어 연결되지 않은 상태로 보이게 하면 손댈 곳이 많다. 상단의 저장 상태 표시(`.save-status-chip`)가 "상태를 보이고, 실패했을 때는 누르면 다시 한다" 는 같은 구실을 이미 하고 있어 그 모양을 따랐다. 상단은 영상 영역 밖이라 mpv 미러가 필요 없다.
- **버튼(`<button>`)이 아니라 저장 상태 표시와 같은 `div` 다.** 버튼은 누른 뒤 포커스가 남아, 스페이스(재생·정지)가 표시를 다시 누른다. 키보드로는 누를 수 없다(남은 한계).
- **30초 간격은 "마지막으로 접속을 시도했거나 접속에 실패한 때" 부터 센다.** 처음에는 직접 누른 것끼리만 셌는데, 그러면 저절로 한 시도가 실패한 직후나 파일을 연 직후에 누르면 몇 초 안에 접속이 두 번 열린다(리뷰 A). 시각은 `performance.now()` 로 잰다(PC 시계를 바꿔도 영향받지 않는다).
- **결과 없이 끝난 시도도 자동 시도 횟수에 넣는다.** 횟수를 되돌리면 그런 시도가 되풀이될 때 정해진 횟수(6번)에서 멈추지 않는다. 그 대신 영상 전환 취소나 엔진 전환이 시도와 겹칠 때마다 자동 시도가 한 번 줄어든다(직접 누르기는 계속 된다).
- **문구는 "· 다시 연결" 로 끝낸다.** 이 앱의 "저장 실패 · 다시 시도" 와 같은 꼴이다.

### 재확인

고친 뒤(`affedc4`) 같은 리뷰어 두 명에게 변경분을 다시 보였다. 둘 다 새로 생긴 결함은 없고 내보내도 된다고 판정했으며, 작은 지적을 더 냈다. 리뷰 A 는 세 판(수정 전, 첫 수정, 리뷰 반영)의 실제 함수를 나란히 돌려 A1 의 틈에서 접속이 0번 → 1번 → 0번, A2 에서 남은 타이머가 0개 → 0개 → 1개, A3 에서 접속이 1번 → 1번 → 0번인 것을 확인했다.

A 재확인 1·2 를 반영한 마지막 커밋(`d5a41b0`)은 리뷰 A 에게 한 번 더 보였다. 새로 생긴 문제는 없고 내보내도 된다는 판정이며, 재확인 1 의 순서(재접속이 파일을 읽는 사이 종료를 시작)에서 접속이 1번 → 0번이 된 것을 네 판을 나란히 돌려 확인했다. 리뷰어가 남긴 참고: 직접 누른 시도가 거절된 직후, 파일 감시를 다시 켜는 짧은 사이에 같은 파일의 영상 전환이 취소돼 토큰만 오르면 누른 사람에게 실패 안내가 빠진다(표시와 다음 차례는 정상). 고치지 않았다.

## 검증

PR 전의 결과다. 스크립트와 기록은 저장소 밖 `output/audits/2026-11-20-collab-rejoin-chip/` 에 둔다.

- 실제 앱 점검(코드의 마지막 커밋 `d5a41b0` 을 패키지한 후보 빌드, 보이지 않는 데스크톱, 실시간 서비스의 주소를 그 앱 인스턴스에서만 막아 서비스에 접속하지 않음). 누르는 것은 모두 Playwright 의 `locator.click()` 이다 — 보이지 않거나 가려진 요소는 누르지 못하고 실패한다.

## 확인했지만 고치지 않은 것

- **실시간 서비스에 닿지 못하는 PC 에서는 새 파일의 첫 저장이 최대 10초 늦는다.** `.bframe` 이 아직 없는 영상의 첫 저장은 방 접속을 먼저 기다린다(`prepareReviewFileBeforeSave`, 방 이름을 첫 저장에 함께 적으려는 것). 서비스에 닿지 못하면 접속 대기 제한(10초)을 다 채운 뒤에야 저장한다. 정원 초과·월 한도 거절은 바로 돌아오므로 해당하지 않는다. v2.16.3-beta 부터의 동작이고(그 전에는 제한이 풀려 있어 끝없이 기다렸다) 정상 종료는 저장을 기다린다. 회귀 점검을 서비스를 막고 돌리다가 드러났다 — 점검이 저장을 기다리지 않고 프로세스를 끝내 그림이 저장되지 않았다. 점검 쪽을 "첫 저장이 끝난 뒤에 끈다" 로 고쳤다.
- **연결된 뒤에 끊겨 다시 못 들어간 경우**(Liveblocks 가 `failed` 를 알림)에는 재접속 기록이 없어 표시도 없다. 이전부터 같다. 그때도 댓글은 파일로 오간다.
- 밝은 테마에서 저장 상태 표시의 "저장 대기 중(재시도)" 도 같은 경고색이라 잘 읽히지 않는다(이전부터).

## 남은 한계

- 표시는 상단에 있다. 앱 전체화면, 버전 비교 화면, 모달이 떠 있는 동안에는 보이지 않는다. 그 화면에서 나오면 보인다.
- 키보드로는 누를 수 없다(마우스·펜·터치만).
- 새 버전을 띄운 사람에게만 적용된다.
- 실제 정원 초과(10명을 채운 방)에서의 모습은 이번에 다시 보지 않았다 — 서비스 사용량을 쓰기 때문이다. 접속 실패 뒤의 길은 사유와 무관하게 같고, 사유별 문구는 자동 검사가 본다.
- 마우스를 올렸을 때의 툴팁이 영상 창에 가려지지 않는지는 확인하지 못했다(보이지 않는 데스크톱에서는 볼 수 없다).

# 간단한 영상 편집 Implementation Plan

> **For agentic workers:** Use superpowers:subagent-driven-development for independent tasks and review the integrated result. The user selected actual development after the interactive timeline design.

**Goal:** 기존 드로잉을 이용하여 두 영상을 자르고 연결하고 정지 구간을 넣어 짧은 MP4를 만든다.

**Architecture:** 리뷰창의 `영상 편집` 버튼에서 전용 편집창을 연다. 비파괴 편집 프로젝트 `.bedit`가 원본 경로, 컷 배치, 제작용 V3 그림을 보관한다. 프리뷰와 출력이 같은 출력 프레임→클립→원본 시간 계산을 사용한다. 기존 리뷰 `.bframe`은 수정하지 않는다.

**Tech Stack:** Electron 28, HTML/CSS/JS, 기존 Fabric V3 런타임, FFmpeg/ffprobe, Node test.

**Spec:** 이 문서의 승인된 범위와 아래 계약. 대화에서 사용자가 선택한 실제 개발 및 선택 컷 드로잉 확장 시안.

## Global Constraints

- `drawingsV3` 레코드에 임의 필드를 추가하거나 레거시 `drawings`에 이중 저장하지 않는다.
- 원본 영상과 기존 리뷰 파일에 쓰지 않는다. 프로젝트/MP4 저장은 전용 대화상자를 사용한다.
- 노드/파일/FFmpeg 접근은 메인 프로세스에 한정하고 전용 편집창 sender만 승인한다.
- `shell:false`, `windowsHide:true`, 배열 인수로 FFmpeg를 실행한다. 취소는 해당 작업만 중단한다.
- 1차 범위: 다중 영상 가져오기/순서/트림/분할/삭제/정지 삽입 및 범위 대체, 실행취소/다시실행, 프로젝트 저장/재열기, 제작용 그림 키프레임/빈 키프레임/유지/레이어, 16:9·9:16·1:1, 맞춤·채움, 원본 음량/음소거+배경음악 하나, MP4 출력과 취소.
- 고급 효과·전환·다중 비디오 트랙은 범위 밖이다. 기존 리뷰 타임라인은 보존하며 편집창에 같은 브랜드의 컴팩트 타임라인을 구현한다.
- 프레임은 출력 FPS 기준의 정수다. 원본 위치는 초로 저장하여 서로 다른 FPS의 원본을 연결한다.
- 컷 트림은 그림을 삭제하지 않는다. 분할 후 오른쪽에서도 이전 그림의 유지 상태를 보존한다. 컷마다 그림 사본을 소유하여 이후 편집은 독립적이다.

## 공통 데이터 및 인터페이스

`shared/edit-project.js`는 CommonJS 및 브라우저 `window.BAEEditProject`에 같은 순수 API를 제공한다.

```js
// createProject() 기본값
{ type:'baeframe-edit', schemaVersion:1, name:'새 편집', fps:24,
  width:1920, height:1080, sources:[], clips:[], music:null }
// source
{ id, path, name, durationSeconds, width, height, fps, hasAudio }
// clip: kind는 'video' 또는 'freeze'. sourceStartSeconds 는 freeze 시 고정 원본 시간
{ id, sourceId, kind:'video', sourceStartSeconds:0, durationFrames:48,
  volume:1, fit:'contain', drawingOffsetFrames:0,
  drawingsV3:null, drawingLayersV1:null }
// music: offsetFrames는 출력 타임라인에서 음악 재생을 시작할 프레임(원본 트림이 아님)
{ sourceId, volume:0.5, offsetFrames:0 }
```

API: `createProject(options={})`, `validateProject(project)` throws on malformed project and returns true; `durationFrames(project)`; `resolveFrame(project, frame)` returns `{clip, clipIndex, source, localFrame, drawingFrame, sourceTime, outputFrame}` or null for empty/outside; `appendSource(project, source)` appends a video clip; `splitClip(project, clipId, localFrame)`; `trimClip(project, clipId, trimStartFrames, trimEndFrames)` removes that many frames from current edges; `moveClip(project, clipId, targetIndex)`; `removeClip(project, clipId)`; `insertHold(project, clipId, localFrame, holdFrames, replace=false)`; all mutations return a deep independent new project; `createHistory(project)` exposes `{get present(), commit(next), undo(), redo(), get canUndo(), get canRedo()}`.

Renderer uses `window.editorAPI`: `pickMedia(kind)` → `{cancelled,sources}`; `openProject()` → `{cancelled,project,path}`; `saveProject(project,saveAs)` → `{cancelled,path}`; `exportVideo({project,overlays})` → `{cancelled,path}`; `cancelExport()`; `onExportProgress(callback)` → unsubscribe; `setDirty(boolean)`; `confirmDiscard()` → boolean. Overlay entries `{clipId,startFrame,endFrame,dataUrl}` use clip-local half-open output-frame intervals and PNG data. Renderer may not supply output file paths. End-user file dialogs are the path authority.

## 구현 및 검토 기록

- 프로젝트 코어는 프레임 계산·순서·트림·분할·정지·실행취소를 담당한다. 클립별 독립 V3 문서와 루트 레이어 정보를 보관하고 기존 `.bframe`을 변경하지 않는다.
- 편집창 전용 preload와 IPC를 추가했다. 원본 경로는 파일 선택과 검증된 프로젝트 열기를 통해서만 허용한다. 임시 파일 검증 후 프로젝트/MP4를 반영하고 취소·덮어쓰기·창 종료 경계를 검사한다.
- 기존 Fabric 드로잉 런타임과 저장소를 새 진입점에서 번들한다. 런타임 원본 및 기존 생성 번들은 수정하지 않았다. 실제 도구 팔레트를 편집 도구줄에 배치한다.
- 출력은 컷별 H.264 영상과 PCM 오디오 중간 파일을 이어 최종 AAC를 한 번 인코딩한다. 컷 경계의 오디오 패딩을 피하고 출력 FPS로 정확한 프레임 수를 맞춘다. 정지 화면은 원본 소리를 끄며 음악은 이어진다.
- 초기 통합 검토에서 빈 V3 문서 수화가 실행취소 이력에 들어가던 문제, 컷 이동 후 선택이 바뀌던 문제, 비동기 이름 입력 유실을 재현하고 수정했다.
- 재생 그림 시간은 실제 표시된 영상 프레임을 따른다. 수동 탐색 중에는 이전 영상과 그림을 숨기고, 정지 구간만 별도 경과 시간으로 진행한다. 빈 레이어는 다른 레이어의 채워진 키프레임을 표시하지 않는다.
- 그림이 많은 프로젝트의 같은 컷 재생에서 불필요한 전체 그림 사본 생성을 제거했다. 수동 탐색·컷 전환·저장 전에 캡처하는 동작은 유지한다. 회귀 테스트에서 23프레임 이동의 사본 생성 횟수 23→0을 확인했다.
- 타임라인 키프레임 조회도 실제 변경 시에만 수행한다. Chrome 재생 검사에서 조회 121회→2회를 확인했다.
- 편집창의 종료 취소가 기존 리뷰창의 종료 준비를 남기던 경계를 수정했다. 종료 시도 ID와 정확한 메인 창·프레임을 검사하며, 취소 시 진행 중 저장을 기다려 입력·자동저장·협업을 복구한다. 반복 종료와 오래된 승인 응답을 차단한다.
- 실제 패키지 검사에서 기본 X/Alt+F4 경로가 저장 확인 전에 리뷰창을 파괴하는 문제도 확인했다. 최종 종료 준비까지 리뷰창을 유지하는 close 가드를 추가했고, 실제 X 닫기 취소·재승인·정상 종료를 검증했다.
- 빌드 전 새 드로잉 번들을 생성하도록 설정했다. 기존 `runtime-profile.test.js`의 빌드 명령 기대값도 함께 갱신했다.

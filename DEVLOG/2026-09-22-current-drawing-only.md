# 현재 드로잉 진입 복구와 구형 작성 도구 제거

## 요청과 확인

- 2.12.6-beta에서 정상 실행 중에도 B 입력 시 최신 배포 폴더로 다시 실행하라는 알림이 반복된다.
- `G:\공유 드라이브\JBBJ 자료실\한솔이의 두근두근 실험실\BAEFRAME\테스트버전 빌드\BFRAME_alpha_v2.exe`는 실제 운영 배포본이다. 팀원은 이 파일의 바로가기를 사용하며 폴더명 때문에 검증판으로 취급하면 안 된다.
- 사용자 PC의 화면/앱을 조작하지 않고 코드·Node/jsdom·패키지 검증으로 진행한다. 내부 독립 리뷰를 사용한다.

## 확인한 원인

- `toggleDrawMode`가 HTML5 재생 또는 아직 준비되지 않은 컨트롤러 상태를 모두 잘못된 배포 폴더로 안내한다. 실행 위치를 검사한 결과가 아니다.
- `initialize()`는 실패/비활성 결과도 영구 캐시하여 준비 실패 후 재시도가 불가능하다.
- 기존 팔레트를 차단했지만 HTML/리스너/구형 DrawingCanvas 입력 엔진은 여전히 생성되어 있었다.
- 정상 live 경로, stable 프로필, 현재 배포의 주요 main/preload/controller 코드는 확인 결과 정상이다. 특정 PC에서 어느 조건이 최초로 실패했는지는 아직 확정하지 않았다.

## 구현 계획

1. 현재 도구의 준비·진입·재시도와 재생 방식 변경 경계를 실제 동작 검사로 재현하고 수정한다. mpv에서 HTML5 재생으로 내려가도 동일한 Fabric 도구를 사용하도록 드로잉 표면의 준비·표시·저장 수명을 재생 엔진에서 분리한다.
2. 구형 팔레트·전용 이벤트·키보드 fallback·작성 엔진을 제거한다. 기존 drawings 데이터의 읽기·표시·저장은 유지한다.
3. 올바른 운영 경로와 바로가기 정책을 문서에 명시한다.
4. 관련 회귀 검사와 독립 내부 리뷰 후 exact merge 빌드, 기존 live 경로 배포, 전체 해시 검증을 완료한다.
5. 완료한 범위와 미확인 실기 검증을 구분하여 사용자 및 요청한 윤성원님 DM으로 전달한다.

## 검증 기록

- 코드/자동 검사 진행 중. 최종 리뷰 SHA와 실제 배포 결과는 릴리스 evidence에 기록한다.
- 초기화 회귀: 수정 전 1 pass / 3 fail, 수정 후 4 pass / 0 fail / 0 cancelled (exit 0). 상태 IPC 실패와 저장 bridge 지연이 재시작 없이 회복되고 동시 호출은 한 번만 구독한다.
- 컨트롤러·단축키: 명시적 HTML5 드로잉 표면에서도 같은 B 활성화/비활성화, 준비되지 않은 표면 차단 포함 64 pass / 0 fail / 0 cancelled (exit 0).
- 초기화·단축키·표시·저장 컨트롤러 합계 138 pass / 0 fail / 0 cancelled (exit 0). 초기 실패 사유를 상태 snapshot에 전달하여 실패 진단이 사라지지 않도록 했다.
- 구형 작성 canvas, 전용 freehand renderer, 별도 browser bundle을 실제 삭제했다. 현재 Fabric의 npm perfect-freehand 의존성은 유지했다.
- 구형 데이터 보존 검사에서 저장된 opacity 0이 1로 바뀌던 기존 결함을 재현해 `DrawingLayer` 기본값 처리도 수정했다. 관련 드로잉 검사 330 pass / 0 fail / 0 cancelled (exit 0).

## 내부 리뷰에서 추가로 찾은 경계

- 드로잉 준비 응답을 기다리는 동안 B 재입력 취소가 준비 promise에 묶여 무시되거나, C로 댓글을 켠 뒤 늦게 도착한 B가 댓글을 닫는 경합을 독립 리뷰에서 재현했다. 취소 의도를 준비 작업에 전달하고 늦은 완료가 새 모드를 덮어쓰지 않도록 동작 검사로 고정한다.
- 화면은 같은 원본 영상의 식별자를 사용하도록 `state.currentFile`을 우선한다. 변환된 임시 MP4의 경로를 저장 식별자로 사용하지 않는다.
- 사용자 요청에 따라 온라인 Codex 봇 리뷰 대신 다른 담당자의 로컬 코드/동작 리뷰를 사용한다. 봇 승인으로 기록하지 않는다.
- 사용자 화면 조작, 앱 실행, 실제 OS 클립보드/네이티브 창 조작, 타 PC 동기화 확인은 수행하지 않는다.

- 추가 독립 리뷰에서 HTML5 host 복구가 화면 준비 전에 재개 요청을 소비하는 경합과, 영상 전환 취소 후 의도 번호만 바뀌어 현재 화면이 무효화되는 결함을 실제 app/controller 조합으로 재현했다. 화면 동기화·ready 후 controller 재조정 순서를 적용하고, 준비 중 작업의 의도 fence와 이미 표시 중인 영상의 수명을 분리했다.
- 구형 그림 데이터가 현재 V3 문서로 자동 변환되지 않는 것을 확인했다. native 재생과 C 정지 화면에서도 기존 PNG를 현재 그림 아래에 읽기 전용으로 합성해 표시를 유지한다.

## 최종 검증 및 릴리스 전달

- 101개 관련 테스트 파일 통합: 2,258 pass / 0 fail / 0 cancelled / 0 skipped, exit 0 (`output/releases/2026-09-22-v2.12.7-beta/regression-approved.log`). GUI 실행 테스트 2개는 사용자 요청에 따라 제외했다.
- 변경 제품 파일과 신규 동작 검사 lint: exit 0, 오류 0, 기존 unused 경고 20. `git diff --check` exit 0.
- 기존 그림 합성/지연 캡처에서는 캡처 후 파일·프레임이 바뀌면 렌더를 건너뛴다. 렌더 대기 후에도 동일 검사를 반복해 새 영상 캔버스를 읽거나 덮지 않도록 했다.
- 독립 내부 리뷰에서 발견한 경합·복구·표시 결함을 수정하고 재검증했다. 최종 SHA 리뷰, merge SHA, exact-merge build, canonical live 전체 해시, 비실행 백업, 요청된 윤성원 DM 결과는 위 릴리스 evidence 폴더에 연속 기록한다.

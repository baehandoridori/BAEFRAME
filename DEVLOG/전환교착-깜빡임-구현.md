## 배경 및 목적

영상 전환 중 드로잉 저장 상태와 죽은 mpv 오버레이 호스트가 맞물리면 다음 영상으로 넘어가지 못했고, 이어붙이기에서는 같은 전역 실패가 남은 항목 전체를 빠르게 `건너뜀`으로 만들 수 있었다. 또한 mpv가 이전 프레임을 유지할 수 있는데도 렌더러가 네이티브 호스트를 숨겨 검은 화면이 노출됐다.

이번 수정은 계획서에 지정된 블록만 변경해 교착의 자기 복구 경로, 사용자가 선택할 수 있는 저장 포기 경로, 전역 실패와 항목 실패의 분리, 재생목록 선택 피드백, mpv 이전 프레임 유지 경로를 추가한다.

## 작업 1: 죽은 오버레이 호스트 교착 복구

### 목표

종료된 mpv 오버레이 호스트를 비활성화하는 요청은 안전한 성공으로 처리하고, 해당 사유가 드로잉 저장 게이트의 영구 차단으로 남지 않게 한다.

### 수정 파일

- `main/mpv-overlay-host.js`
- `renderer/scripts/modules/fabric-drawing-pilot-controller.js`
- `scripts/tests/mpv-overlay-host.test.js`
- `scripts/tests/fabric-drawing-persistence-controller.test.js`

### 구현 내용

- 죽은 호스트의 disable 요청을 no-op 성공으로 처리했다.
- export 실패 사유에서 `hostUnavailable`을 분리해 컨트롤러까지 전달했다.
- 호스트 부재 시 차단 래치를 만들지 않되 현재 영상의 소유권과 저장 컨텍스트는 보존해, 새 호스트가 같은 영상을 다시 수화하도록 했다.

### 실제 리스크

실제 mpv 종료 후 재생성되는 UI 전체 경로는 사용자 지시에 따라 실행하지 않았다. 호스트 응답 계약과 컨트롤러 상태 정리는 자동 테스트로 검증했다.

## 작업 2: 저장 포기 탈출구와 이어붙이기 전역 실패 중단

### 목표

살아 있는 호스트의 실제 저장 실패가 영상 전환을 영구 차단하지 않게 하고, 이어붙이기의 전역 저장 실패를 개별 항목 실패로 기록하지 않게 한다.

### 수정 파일

- `renderer/scripts/modules/fabric-drawing-pilot-controller.js`
- `renderer/scripts/app.js`
- `scripts/tests/fabric-drawing-pilot-source.test.js`
- `scripts/tests/playlist-continuous-runtime.test.js`

### 구현 내용

- 컨트롤러 공개 API에 저장 차단 상태만 해제하고 현재 영상 소유권·롤백·저장 컨텍스트는 보존하는 탈출 메서드를 노출했다.
- 사용자 주도 전환에서 저장 실패 시 확인 대화상자를 거쳐 저장을 포기하고 전환할 수 있게 했다.
- 한 로드에서 포기를 승인하면 2차 저장 게이트를 다시 묻지 않으며, 이미 세운 입력 펜스와 이전 영상 롤백을 그대로 유지한다.
- 이어붙이기에서는 fabric 전역 실패 사유를 read-and-clear하고 전용 토스트 한 번으로 세션을 중단하며, 항목을 `건너뜀`으로 오염시키지 않는다.
- 보호 대상으로 지정된 `if (!fabricReadyForVideoChange || !canContinueVideoLoad()) return false;`는 변경하지 않았다.

### 실제 리스크

확인 대화상자의 사용자 체감은 UI 수동 검증 없이 소스 계약 테스트로 확인했다. 포기 뒤 대상 검사 실패·롤백 복원은 컨트롤러 행동 테스트로 추가 검증했다.

### 실제 리스크

표시의 실제 시각 상태는 UI 수동 검증에서 확인하지 않았고, 실패 경로의 소스 계약과 mpv 자동 테스트로 검증했다.

## 작업 4: 재생목록 선택 반응과 실패 복원

### 목표

클릭 즉시 선택 상태를 보여 주고, 로드 실패나 예외가 발생하면 최신 클릭에 한해 이전 선택으로 복원하며, `건너뜀`/`오류` 항목은 클릭으로 다시 시도할 수 있게 한다.

### 수정 파일

- `renderer/scripts/modules/playlist-manager.js`
- `renderer/scripts/app.js`
- `scripts/tests/playlist-continuous-runtime.test.js`

### 구현 내용

- 로드 시작 전에 현재 선택 표시를 갱신한다.
- 선택 토큰과 현재 항목 가드를 통과한 실패만 실제 재생 중인 `state.currentFile`의 현재 인덱스로 롤백한다.
- `SKIPPED`와 `ERROR`만 `IDLE`로 되돌려 재시도하고, 파일 부재인 `MISSING`은 유지한다.
- 클릭 전환에도 `holdPreviousFrameUntilReady: true`를 전달한다.

### 실제 리스크

빠른 연속 클릭과 시각적 하이라이트 타이밍은 지정 소스 테스트와 재생목록 자동 테스트로 검증했다.

## 작업 5: mpv 이전 프레임 유지

### 목표

mpv→mpv 연속 전환과 재생목록 클릭 전환에서 네이티브 호스트를 숨기지 않고 이전 프레임을 유지한다.

### 수정 파일

- `renderer/scripts/modules/mpv-surface-policy.js`
- `renderer/scripts/app.js`
- `scripts/tests/mpv-runtime-source.test.js`

### 구현 내용

- 드라이브 로딩 pill을 mpv 차단 서피스에서 HTML 미러 서피스로 옮겼다.
- mpv→mpv, 비오디오, 비엔진 교체, 이전 프레임 유지 요청 조건에서만 심리스 전환 플래그를 켠다.
- 심리스 전환 중에는 준비 상태여도 네이티브 호스트를 계속 표시한다.
- 로드 토큰이 소유한 게이트로 심리스 상태를 관리하고, `finally`에서는 자신이 소유한 상태만 해제한다.

### 실제 리스크

해상도가 다른 파일 사이에서는 계획서가 수용한 1~2프레임 수준의 짧은 플래시가 남을 수 있다. 실제 영상 경계의 체감과 미러된 로딩 pill의 시각 품질은 UI 수동 검증 없이 자동 테스트로만 확인했다.

- 기준 테스트 첫 실행에서 `canvas` 네이티브 바인딩이 없어 1종이 실패했다. `npm rebuild canvas`로 개발 의존성만 복구했고 추적 파일은 바꾸지 않았다. 복구 후 기준선과 최종 테스트가 각각 25/25 PASS였다.
- 부록 B의 전역 `npm run format`은 사전 검사에서 수정 금지 파일인 `renderer/scripts/lib/mpv-fabric-overlay.iife.js`와 `renderer/scripts/modules/mpv-fabric-overlay-runtime.js`를 재작성하는 것으로 확인됐다. 절대 규칙과 충돌하므로 전역 포맷은 적용하지 않았다. 허용 파일만 대상으로 한 포맷 시도도 대규모 줄바꿈 변경을 만들었기 때문에 즉시 되돌렸고 최종 제품 diff에는 포함하지 않았다. `npm run lint:fix`는 오류 0으로 통과했다.
- 부록 A의 수동 시나리오 1~5는 사용자 지시에 따라 실행하지 않았다. 앱 화면·마우스를 사용하는 테스트는 최종 검증에서 제외했다.
- 작업 4의 계획서 방식인 `previousIndex` 캡처 롤백과 작업 5의 전역 불리언 무조건 해제는 구현 후 Codex 리뷰에서 빠른 연속 전환 경쟁 조건이 확인됐다. 계획서 범위 밖 리팩터링 없이 같은 네 파일 안에서 실제 현재 파일 기반 롤백과 로드 토큰 소유권 게이트로 보완했다.
- 작업 1·2의 계획서가 지정한 `settleWithoutPilotVideo()` 방식은 현재 영상 소유권까지 조기 삭제했고, 이어붙이기 토스트 1회라는 목표와 계획서 after 블록도 서로 모순됐다. Codex 2차 리뷰에 따라 같은 명시 블록 안에서 비파괴 포기, 호스트 재수화, 단일 토스트 구조로 보완했다.
- 비파괴 포기로 바꾼 뒤에는 최종 pull 실패가 지운 활성 복귀 의도를 rollback에서 되살려야 하는 성공 전환 경로가 추가로 드러났다. Codex 3차 리뷰에 따라 진행 중 전환에 한해서만 해당 의도를 복원했다.

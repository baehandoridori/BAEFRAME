# 재생목록 영상별 버전 추가·비교 분리

## 요청과 범위

재생목록에서 각 영상에 맞는 버전을 추가하고 비교할 수 있어야 한다.
현재 작업은 영상마다 자기 버전 목록과 비교 대상을 유지하는 동작을 기준으로 한다.
재생목록 전체를 같은 버전 번호로 일괄 전환하는 별도 기능은 포함하지 않는다.
앞선 댓글 귀속 수정(PR #223)을 포함한 origin/main에서 별도 worktree로 진행한다.

## 원인과 수정

- `VersionManager.setCurrentFile`이 이전 영상의 수동 버전을 비우지 않았고,
  app도 새 영상의 저장 목록이 비어 있으면 복원을 생략해 이전 버전이 남았다.
  새 영상에서 목록을 초기화하고 빈 저장 목록까지 복원한다.
- 전역 isScanning 때문에 B 검색을 생략하고 늦은 A 결과를 받아들였다.
  검색 세대를 구분해 새 검색을 진행하고 폐기된 결과·오류·finally 상태 갱신을 무시한다.
- 저장 매니저의 manualVersions 배열을 화면 매니저가 직접 공유했다.
  복원 시 복사해 화면 변경이 저장 데이터에 중복으로 들어가지 않도록 한다.
- 버전 추가·편집 모달은 시작한 영상/화면 세대/저장 매니저를 캡처한다.
  중간에 영상이 바뀌거나 전환 중이면 다른 영상에 추가·편집하지 않는다.
- 버전 선택과 비교는 현재 영상 준비 후 허용한다. 비교 목록에 현재 영상이 없으면
  첫 번째 다른 영상을 대신 열지 않는다. Windows 경로 대소문자/구분자를 정규화해 찾는다.
- 기존 keepVersionContext 전환, 파일 형식, 사용자 데이터는 보존한다.

## 검증

- 수정 전 실패: A 수동 버전의 B 전이, 늦은 A 검색/초기화 이후 검색,
  파일 선택/번호 입력 중 대상 변경, 로드 중 잘못된 비교, 전환 중 버전 선택.
- `npm run test:version`: exit 0, 11 pass / 0 fail / 0 cancelled.
- `npm run test:playlist`: exit 0, 375 pass / 0 fail / 0 cancelled.
- `npm run test:previous-review`: exit 0, 57 pass / 0 fail / 0 cancelled.
- 변경 JS ESLint errors 0, 기존 unused 경고 20. diff check 통과.
- 실제 소스 앱: 익명 A/B/C와 각각 다른 수동 버전 파일을 사용.
  A/B에 각 1개씩 저장한 뒤 A→B→C→A 전환, 복원 목록과 디스크 manualVersions를 확인.
  실제 비교 화면의 좌우 파일이 A끼리/B끼리인지 확인하고 스크린샷을 남겼다.
- 최초 앱 검사에서 재생목록의 초기 자동 선택 로드가 끝나기 전에 추가를 시도해
  정상적인 전환 차단에 걸렸다. 테스트가 준비 완료를 기다리도록 수정한 뒤 통과했다.
- 네트워크 차단, 익명 userData, 테스트용 파일 선택 응답 사용. 실사용자 파일 수정 없음.
  다른 PC 협업/Drive 동기화와 실물 태블릿 검증은 미수행이다.

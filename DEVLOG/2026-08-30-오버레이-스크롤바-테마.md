# 오버레이 스크롤바를 배프레임 테마에 맞춘다 (PR #208)

- 브랜치: `claude/드로잉-후속4` → main (`48a3fb2`)
- 버전: 2.6.2-beta
- 코덱스 리뷰: 1라운드, `Didn't find any major issues` (`48e4556f99`)
- 검증: 25개 스위트 2,284 pass / 0 fail, Electron 레이아웃 2 pass
- 배포: 공유 드라이브 `테스트버전 빌드`, 82파일 해시 `MismatchCount=0`

## 증상과 원인

브러시 설정을 열면 팔레트에 **윈도우 기본 스크롤바**(밝은 회색 막대 + 위아래
화살표 버튼)가 그려져 어두운 팔레트 위에 홀로 튀었다.

**오버레이는 별도 BrowserWindow 라 `renderer/styles/main.css` 를 불러오지 않는다.**
본체에는 테마 스크롤바가 있지만(main.css 의 `Scrollbar` 절) 오버레이 스타일시트
(`main/mpv-overlay-host.js` 안의 문자열)에는 아무 규칙도 없어 크로뮴이 OS 기본
막대를 그렸다.

**오버레이에서 본체와 같아 보여야 하는 것은 전부 이 함정에 걸린다.** 폰트·색
토큰·포커스 링 등 앞으로 추가하는 것도 오버레이 스타일시트에 따로 적어야 한다.

## 조치

본체와 같은 값 — 폭 8px, 트랙 투명, thumb `rgba(255,255,255,0.1)` 반경 4px,
hover 0.18, corner 투명. **규칙을 하나라도 적으면 크로뮴이 커스텀 렌더로 넘어가
화살표 버튼도 함께 사라진다.**

Electron 28 = 크로뮴 120 이라 표준 `scrollbar-color` 는 안 먹는다.
`::-webkit-scrollbar` 가 맞는 수단이고, main.css 도 같은 방식이다.

## 테스트

값을 손으로 베낀 것이라 본체 테마가 바뀌면 소리 없이 어긋난다. 그래서
**main.css 에서 실제 값을 뽑아** 대조한다(폭·thumb 색·모서리 반경).

선택자는 **줄 처음에 앵커**해야 한다. 안 그러면 `.playback-controls-scroll::` 같은
한정 규칙이 먼저 잡혀 엉뚱한 값(0.18/999px)과 대조하게 된다 — 처음 쓴 정규식이
실제로 그렇게 잡혀 통과 대신 오답으로 실패했다.

되돌려 실패 확인: 규칙을 지우면 `오버레이에 스크롤바 thumb 규칙이 없다 — 윈도우
기본 막대가 나온다` 로 실패한다.

## 함정

이 CSS 는 JS **템플릿 리터럴** 안에 있다. 주석에 백틱을 쓰면 문자열이 끊겨
`SyntaxError` 가 난다(작성 중 한 번 겪었다).

## 남긴 것 — 스크롤 자체

"칸이 작아지는" 것은 팔레트 본문이 `max-height: 70vh` 를 넘으면 스크롤되도록
**설계된 동작**이다. 브러시 설정 패널이 303px 이라 짧은 영상 창에서는 여는 순간
그 한계에 닿는다. 이번 변경은 스크롤바 **모양**만 맞춘 것이다.

스크롤 자체를 없애려면 팔레트 구성을 다시 짜야 한다(예: 브러시 설정을 팔레트
옆에 붙는 별도 패널로 빼기). 별도 라운드 감이다.

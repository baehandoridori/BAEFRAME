# mpv 협업 화면 가림 수정 개발 로그

> 기준 스냅샷: `origin/main` `bf20e708`. 작업 브랜치: `codex/baeframe-mpv-liveblock-visibility`. 버전: 2.0.1-beta → **2.0.2-beta**.

## 문제

mpv 플레이어는 일반 웹 화면보다 위에 놓이는 별도 Windows 창이라 CSS의 `z-index`만으로는 협업 화면을 올릴 수 없다. 이 때문에 Liveblocks의 원격 커서, 작업 인원 패널, 재생 동기화 패널, 협업 연결 파동, 원격 드로잉 스트로크와 일부 편집 보조 화면이 mpv 뒤에 가려질 수 있었다.

## 근본 원인과 수정

1. **표시 정책 분산**: mpv를 잠시 숨길 화면과 mpv 위에 복제할 화면의 목록이 `app.js` 여러 곳에 따로 있었다. `mpv-surface-policy.js`의 단일 등록부로 통합하고, 패널의 자식이 영상 영역으로 펼쳐지는 경우까지 실제 겹침을 계산한다.
2. **원격 커서의 두 전송 경로**: 전체 오버레이 상태와 커서 전용 전송이 같은 HTML을 덮어써 오래된 상태가 되살아날 수 있었다. 커서는 전용 경로 하나만 사용하고 순번이 낮은 갱신은 거부한다.
3. **네이티브 드로잉 중 커서 정지**: Fabric 드로잉 창이 포인터를 받는 동안 메인 화면이 mousemove를 받지 못했다. 네이티브 오버레이가 좌표를 정규화해 메인 화면의 Liveblocks presence로 돌려보내도록 연결했다.
4. **전용 미러 누락**: 원격 스트로크와 협업 연결 파동을 mpv 오버레이에 직접 그리는 경로를 추가했다. 스크럽 미리보기와 합성 레이어 변형 핸들·스냅 가이드도 공통 HTML 미러 대상에 포함했다.
5. **원본 커서 숨김 조건 오류**: mpv 모드 여부가 아니라 네이티브 호스트가 실제로 보이는지를 body 상태로 추적해, 패널 때문에 mpv를 잠시 숨길 때 원본 커서가 즉시 다시 보이도록 했다.
6. **빠른 열기·닫기 경쟁 조건**: 먼저 보낸 표시 요청이 늦게 끝나 최신 숨김 상태를 되돌리지 않도록 요청 순번을 검증하고, 엔진 종료·전환 시 진행 중인 요청을 무효화했다.
7. **커서 경계와 표시 일치**: 원격 커서 IPC는 현재 메인 화면에서 온 정확한 2필드·256KB 이하 데이터만 허용한다. 원격 스트로크의 투명도도 mpv 미러에 함께 전달한다.
8. **스크럽 미리보기 종료 감지**: 표시할 때는 `active` 상태만 복제하되, 닫히며 `active`가 제거되는 순간도 감지하도록 무조건 관찰 선택자를 분리했다.

## mpv 위 표시 정책

| 방식 | 대상 예시 | 처리 |
|---|---|---|
| 잠시 mpv 숨김 | 작업 인원 패널, 재생 동기화 패널, 메뉴·팝업·모달 | 실제 영상 영역과 겹칠 때만 mpv 숨김 |
| 공통 HTML 미러 | 스크럽 미리보기, 전체화면 표시, 합성 변형 핸들·스냅 가이드 | mpv 오버레이에 시각 복제 |
| 전용 미러 | 원격 커서, 원격 스트로크, 협업 파동, 댓글·토스트·합성 레이어 | 각 데이터에 맞는 전용 동기화 경로 사용 |
